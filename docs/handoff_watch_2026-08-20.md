# 引き継ぎ — 見守り / 暗所ロボット（2026-08-20 時点）

**新しいリポジトリとチャットで、これだけ読めば再開できる形にしてある。**

---

## 北極星

> 暗所で、**移動しながら場を形成し、その場を読んで移動する**ロボット。
> 閉じる環: 移動 → 測定 → 場への堆積 → 場を読む → 移動。
> LLM は入らない（**L5 不在**）。場を読んで動くだけの弱い AI で環が閉じる。
> **欠測は禁止ではなく移動の動機**である（禁止にすると場が形成できない）。
> **移動することが測定**であり、軌跡が測定の履歴になる。
> 蒸発によって古い測定が薄れ、**再訪が強制される**。地図が現在の部屋に追従する。

### 上位の使命との関係

上位の使命（制御不能な AI の抑止）は **LLM のスケーリング則にかかる話**であり、
**場を読む弱い AI を目指すこの系では既に満たされている。**
**L5 を置かない設計そのものが充足**であって、後から満たすべき課題ではない。
→ **後から LLM を足す設計余地を残さない。** 余地を残すと
「いずれ足す前提の穴」になり、主張が「まだ足していない」に変わる。

## 決めた設計と、その理由

| 決めたこと | 理由 |
|---|---|
| **場を 3 次元にする** | 階段と 2階で同じ (x,z) に床が 2枚。空中の障害物がある。**2次元からは情報を復元できない**（机と吊り照明が同じ高さなら区別が消える）。深度は元から 3次元 |
| **疎に持つ** | 配列は全セルが既定値を持ち、それは**「欠測をゼロで埋める」そのもの**。疎なら**エントリが無い = 観測していない**が自然に出る。**性能は結果であって根拠ではない** |
| **L0 は点群と無効レイを持つ** | **センサが返したものをそのまま持つ。「値が無い」と「距離が無限」は別の測定結果である** |
| **L5 不在** | 弱い AI で環が閉じることの実証。**後から足す余地を残さない** |
| **鮮度の場は拡散させない** | 拡散すると見ていない隣接セルに鮮度が染み出し、**見ていない場所が見たことになる**。deposit と evaporate のみ。**通行の場は拡散してよい** |

## 間違えた設計と、なぜ間違えたか

**ここが一番価値がある。**

### 走査済みの定義を 3回外した

| # | 定義 | 何が起きたか |
|---|---|---|
| 1 | メッシュ表面から **6セル（48cm）以内** | **部屋の中央が走査外**になった。足元の印が出ず（`n=0`）、境界は部屋の形でなく**表面から 48cm の殻**。しかも **6 という値は距離場の飽和値ですらなく、こちらが置いた定数**だった（飽和は 7.97 セル） |
| 2 | その床の**列に固体があるか** | **壁の外側まで含んだ**。実測 **8.19 m² 対 6.75 m²**、**1.44 m²（部屋の 21%）が過剰包含**。機体にとっては**壁の向こう側を通行可能と読んで進む領域**だった |
| 3 | **床の境界ポリゴンの内側**（`ARPlane` の `Floor`） | 正しい。**近似をやめて API を使った** |

**どれも実機で見るまで気づかなかった。機体に載せていたら 3回とも衝突している。**

**根本原因**: 「部屋の内側」という**主張を先に決めなかった**。
決めていれば、床の境界ポリゴンに 1回で到達していた。

### 2次元を選んだ理由が、表示の都合と性能だった

主張が「**この人の滞在**」（面）から「**この構成が測れた空間**」（体積）へ変わったのに、
**2次元という決定を持ち越した**。

根拠にした2つは**どちらも北極星と無関係**だった:
- **表示の都合**（頭のセルが目の位置に描かれて見えない）→ **描画の問題**であって
  場の次元の問題ではない。3次元で持って床面だけ描けばよい
- **性能** → 疎に持てば済む

### パネルが箱からはみ出て、装着者が 4回判定不能になった

**9行に対して箱は 620×240 でおよそ 6行ぶん。**
装着中に確認できなかった項目は、どれも**実装されていなかったのではなく
箱から押し出されていた**:

| 件 | 何行目だったか |
|---|---|
| 凡例が無い（**2回のセッションを潰した**） | 8行目 |
| `描画 n=` が読めない | 6行目 |
| 格子と確からしさが見つからない | 7行目 |

**項目を足すたびに下が押し出される構造**だった。**足すことが壊すことになっていた。**

対処: **5行へ**（刻印 / 状態 / 段 / 凡例 / 警告）、**警告は1行に集約**して
**検査を足しても行数が増えない形**にし、**行が箱に収まることをテストで固定**した。

## 実機セッションの型

```
capture_session.ps1（アーム） → restart_app.ps1（起動） → 装着
  → 外す → stop_capture.ps1 → ログ解析
```

- **アームが起動より先。** 逆にすると起動時にしか出ない情報
  （部屋の形・格子・平面の一覧）を取り落とす
- **`deploy.ps1` は起動しない。** `build_quest.ps1` と `deploy.ps1` は
  **`-Watch` を必ず付ける**（引数なしはエラー）
- **装着中は判断しない。** 指示・質問・生存報告もしない。
  ログ監視と記録に徹し、外してから報告する
- **確認項目は項目名ではなく画面の見え方で書く。**
  「格子と確からしさを見て」ではなく
  「**パネルの文字が 5行あるか**」「**床の青いマスが全部灰色になるか**」
- **ビルド後にコミットしない**（刻印と HEAD がずれる）。
  生成物があるなら**コミット → ビルド**の順

操作方法は `docs/watch_controls.md`（**未使用の入力も明記してある**）。
