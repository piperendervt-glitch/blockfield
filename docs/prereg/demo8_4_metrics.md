# Demo 8 第4段 事前登録 — コロニー場

登録日: 2026-08-11 / 対象タグ: demo-8.4.x
方針: roadmap v10 Demo 8 第4段に対応。繁殖の痕跡を種ごとの場と
して敷設し、繁殖判定から「相手個体の探索」を除去し、群れの創発を
観察する。第4.5段(進化本体)の土壌を整える。

## 設計判断(2026-08-11 確定、経緯は会話記録)

- 判断1: コロニー場は3枚(Sheep用・Pig用・Wolf用)。狼も繁殖して
  いる(Demo 8.5 以降 IsAnimal は常に true)ため対称に扱う。
  狼のパックは生態的にも自然で、第4.5段で狼の群れ度も進化対象に
  なりうる
- 判断2: 盗聴(他種のコロニー場を読む)は器だけ作り重み0で寝かせる。
  第4.5段の進化が盗聴を発見するかという問いとして温存する。
  手で入れた盗聴より進化が発見する盗聴の方が研究価値が高い
- 判断3: breedChance の場による変調は第4段では入れない。
  第4.5段の prereg 時に「変調を入れてから進化を回す」順序で判断
- 主目的の確定(実装調査 2026-08-11 より): 繁殖は既に O(A) であり
  負荷の漸近的削減は期待できない。本段の目的は
  (a) 相手個体という概念の除去(コードの単純化)
  (b) 群れの創発
  (c) 第4.5段の土壌
  であり、負荷削減は主軸ではない
- breedCooldown は場に移さない(移送限界の2例目。主語を個体から
  場所に替えると機能が消える。theory_notes.md §4 参照)

## スコープ

- K1: ColonyField 3枚の追加(Sheep/Pig/Wolf)。繁殖成立時に
  出生セルへ deposit(RNG 非消費)。拡散・減衰は既存 ScalarField
  の機構を使用
- K2: 結合行列の器(FieldCoupling)の導入と、既存2結合
  (死→植生の成長促進、踏み荒らし→植生の成長抑制)の移設。
  純粋なリファクタリングであり挙動不変
- K3: 繁殖判定の場化 — FindBreedPartner(隣接4近傍の相手個体
  探索)を「自セルのコロニー場(自種) ≥ colonyBreedThreshold」に
  置換
- K4: 群れ行動 — 移動重みに w_colony(自種のコロニー場への重み)を
  追加。他種のコロニー場への重みも器として持つが初期値0(判断2)
- K5: SimRunner 拡張 — ランダム対照の並走と群れ指標の出力
  (実装は 4a の後、4c の前)
- K6: 判定

## リスクと想定される論点(実装前の記録)
- 4b で繁殖の空間構造が変わる: 従来は「相手が隣にいる」が条件

  あった場所」で単独でも繁殖できてしまう — これは有性生殖から
  実質的な単為生殖への変更である。生態的な意味の変更を許容するか、

  折衷にするかは、4b の実測(M2 が範囲内に収まるか)を見て判断する。

# 追記1 (2026-08-12): 段階 4a の実装で変えたこと

結果の記録は [demo8_4_checklist.md](demo8_4_checklist.md) にある。
ここには**事前登録から外れた判断**だけを書く。

## 変更1: コロニー場の拡散係数を 0.1 → 0.02 にした

事前登録（「τ の初期設計」）は「拡散係数は fear と同程度（0.1）から開始」
としていたが、実装して測ったところ**この設定では場が見えない**。

理由: 痕跡1つが持てる総量は「deposit × τ」で頭打ちになる。
繁殖は 1000ティックあたり 7.25 回（48シード実測）しか起きず、
死（餓死37.4＋捕食22.7 = 60.1回）の 1/8 で、さらに種で3分割される。
そこへ拡散率 0.1・1パスを掛けると τ の寿命のあいだに σ≈4.5セルまで広がり、
ピーク値 `M/(4πDt)` が**表示下限 0.02 に一度も届かない**。
場は存在するが、読み出しにも表示にも使えない。

これは第1段（獲物場を広げすぎて高値セルが92.5%になり情報量が落ちた）、
第2段（墓場は拡散パスを増やすほど狭くなる。35セル→3セル）で
確立した原則と同じ現象である。

死の場・踏み荒らし場と同じ **0.02・1パス**（到達距離 L≈1.4セル）に揃えた。
τ・deposit は事前登録どおり（400 / 1.0）。
4c で `w_colony` と一緒に掃引する対象であることも変わらない。

## 変更2: 表示テストの標本を 1シード → 24シード合算にした

`Display_FieldScalesMatchTheMeasuredDistribution` は
「0.02以上のセルが20個以上」を分布判定の前提にしている。
コロニー場は 48シード中 豚11 / 羊28 / 狼33 のシードで**1セルも立たない**ため、
1シードではこの前提を満たせない。

標本の足りない場をテストから外すのではなく、標本のほうを増やした
（事前登録の「表示基準値は実測分布から決める」を守るため。
CLAUDE.md「生態系の判定は最低48シード」と同じ理由）。
あわせて `EcologyStats.FieldDisplayScale` の実測表を
3シード×1500t から 48シード×3000t に取り直した（既存の場の基準値は変更なし）。

## 4b の着手前に決めること（4a の実測から浮上した論点）

事前登録の 4b は「自セルのコロニー場（自種）≧ `colonyBreedThreshold`」で
繁殖の可否を決める。しかし 4a の実測では、羊・狼はシードの半分以上で
コロニー場がどこにも立っていない。場は0から始まるので、

  最初の繁殖が起きない → 場が立たない → 永久に繁殖しない

という自己閉塞がある。**閾値の選び方だけでは解けない。**
事前登録が「閾値は実測で決める」としていた前提（従来の繁殖頻度を
近似する値が存在する）が成り立っていない。

4b の prereg 追記で、少なくとも次のどれを採るか決めてから実装する:

- (a) 出生だけでなく繁殖可能な個体の滞在でも薄く書く（場が立ち上がる経路を作る）
- (b) 閾値方式ではなく `breedChance` の変調にする（場が0でも従来の確率が残る。
      ただし「判断3: 変調は第4段では入れない」と衝突するので、その判断の見直しになる）
- (c) τ・`colonyDeposit` を上げて痕跡を長く濃くする（4c の掃引と干渉する）
- (d) リスク欄の折衷（場 ∧ 近傍の同種密度）に最初から寄せる

# 追記2 (2026-08-12): コロニー場を二層にする（4a への追補）

追記1が「4b の着手前に決める」とした自己閉塞（(a)〜(d)）への判断。
**案(a) 滞在 deposit を採用する。**

## 変更: コロニー場の定義を二層にする

「繁殖の痕跡」から、

| 層 | 誰が書くか | 量 | パラメータ |
|---|---|---:|---|
| 存在の痕跡 | 生きている動物が毎ティック、自分のいるセルへ | 0.01 | `colonyPresenceDeposit` |
| 繁殖の痕跡 | 繁殖が成立したとき、出生セルへ | 1.0 | `colonyBreedDeposit`（旧 `colonyDeposit`） |

の二層に変える。どちらも自種の場だけに書き、RNG は消費しない。

### 理由1: 繁殖 deposit だけでは場が立たない（実測）

4a の実測で、48シード中 羊28 / 狼33 のシードでコロニー場が1セルも立たなかった。
場は0から始まるので、4b の閾値判定は

  最初の繁殖が起きない → 場が立たない → 永久に繁殖しない

という自己閉塞を起こす。閾値の選び方では解けない。

### 理由2: 置換元と意味が揃う（これが本質）

置換対象の `FindBreedPartner` が判定しているのは
**「隣に相手が存在するか」**であり、「隣で繁殖があったか」ではない。
存在の痕跡こそが置換元と意味の揃った空間統計であり、
主語変換テスト（theory_notes.md §4）を正しく通過する。

繁殖 deposit のみの設計は置換元と意味がずれており、
**自己閉塞はそのずれの症状だった。**
追記1では「閾値の前提が成り立っていない」と書いたが、
正しくは「場の定義が置換元と違っていた」である。

### 理由3: 生態的にも存在が発する

生物のコロニーフェロモンも存在そのものが発する。
繁殖イベント限定のほうが不自然だった。

### 不採用にした案

- **(b) `breedChance` の変調**: 判断3（第4段では変調を入れない）の蒸し返しになり、
  変数が1つ増える。判断3はそのまま維持する
- **(c) τ・deposit を上げる**: 立ち上がりがシード依存でばらつき、
  4c の掃引とも干渉する
- **(d) 折衷（場 ∧ 近傍の同種密度）**: 個体の探索が残るので
  4b の主目的（相手個体という概念の除去）が達成できない。
  純粋な場化が壊れたときの後退先として温存する

## 結果（48シード×3000ティック）

- **痕跡が立たないシードが 豚11 / 羊28 / 狼33 → 全種で 0/48 に解消**。
  1シードあたりの痕跡セル数（0.02以上）は 豚 523 / 羊 361 / 狼 182
- **M0b 相当の再確認: 除外ハッシュ 192/192 一致・全体ハッシュ 0/192 一致**
  （4条件 × 48シード）。生態指標はビット単位で不変
- 表示基準値を 0.10 → **0.05** に更新した（90%点が 0.085〜0.096 →
  0.047〜0.050 に下がったため。基準値据え置きだと比が 0.47〜0.50 で
  許容下限を割り、下地の濃淡が潰れる）

数値の詳細は [demo8_4_checklist.md](demo8_4_checklist.md) を参照。

## 4b への引き継ぎ

`colonyBreedThreshold` は、二層になったことで**層の選択**という意味を持つ:

- 0.02〜0.05 付近に置く → 「自種がよく居る場所」で繁殖できる
  （＝ `FindBreedPartner` に近い意味）
- 0.3 以上に置く → 「過去に出生があった場所」でしか繁殖できない
  （＝ 集落の固定化。単為生殖の懸念が強く出る側）

事前登録の「従来の繁殖頻度を近似する値を実測で選ぶ」は、
この二層の上でなら成立する。4b で分布を取り直して決める。
