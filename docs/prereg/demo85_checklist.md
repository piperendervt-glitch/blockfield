## 実機セッション（2026-08-11 07:59）: M5 判定不能

**草が実機で1つも表示されず、M5（草の高さで場の値が読めるか）が判定不能。**
FPS がパネル上でグラフに隠れて読めず、M6 も判定不能。
修正と再判定は帰宅後。

### 原因A（決定的）: `GrassView` がシーンに含まれていなかった

`SceneBootstrap` は**シーンを生成する** Editor スクリプトで、
書き換えただけではシーンに反映されない。段階4で `GrassView` を追加したあと
**シーンを再生成していなかった**ため、APK に草の描画コンポーネントが
存在しなかった（`Main.unity` の最終更新は 8/9 20:57、`GrassView` の出現数 0）。

エディタ確認で草が見えたのは `TerrainPreview` が別経路で描画しているため。
**エディタで確認できる範囲と実機の構成が食い違う**ことが見落としの構造。

さらに `SceneBootstrap.CreateMainScene` は**シーンが既に存在するとスキップ**する
実装だったため、単に実行するだけでは再生成されなかった
（既存シーンを削除してから実行する必要がある）。

### 原因B（Aを直しても残る）: セッション長で草が閾値に届かない

実機 tick 408 時点:

| 項目 | 値 |
|---|---:|
| 適性セル | 4,504 |
| 草の総量 | 314 |
| **適性セルあたり** | **0.070** |
| 表示閾値の下限 | 0.16 |

ロジスティック成長は立ち上がりが緩やかで、0から始めると平衡
（適性セルあたり約0.135）まで約1,500ティックかかる。
**実機セッションは5分＝約400ティック**（CLAUDE.md）しかない。

エディタ確認手順にも「400ティックでは濃いセルが1つも無い」と
自分で書いていたにもかかわらず、セッション長との矛盾に気づいていなかった。

### 原因C（該当せず）: 座標系は正常

部屋地形は天井 cellY=50 で負のセルYは発生していない。
`GrassView` の高さ計算 `surfaceY * cell` は、実機で正常表示されている
`FieldOverlayView` の `localY = surfaceY * cell` と完全に同一。
オーバーレイは実機で表示できていた（ログに `[FieldOverlay] 表示: Vegetation`）。

## 出発前の暫定対処（2026-08-11 08:20）

1. **`initialVegetation = 0.13` を追加**（原因Bの暫定対処）。
   ワールド生成時に適性セルへ `suitability × 0.13` を入れる。
   RNG を消費しないので決定論は保たれる。
   ヘッドレス実測で **400ティック時点に3段階すべてへセルが入る**
   （高41 / 中134 / 低273）。
2. **`GrassView.DrawnCells` をパネルとログに出す**（原因の切り分け用）。
   `-1` なら `GrassView` 自体が配線されていないことを示す。
3. **シーンを再生成**（原因Aの修正）。`Main.unity` に `GrassView` が
   含まれることを確認済み。

### 暫定対処に伴う基準値の変動（正式な改定は帰宅後）

`initialVegetation` は初期条件を変えるため、いくつかの基準値が動いた。

## 暫定対処の撤回（2026-08-11、同日）

**`initialVegetation` の既定を 0.13 → 0 に戻した（撤回）。**

理由:
- **ティック1から場が全面に広がる状態は、世界が立ち上がっていく過程の
  観察を損なう。** これは本プロジェクトが見ようとしているもの
  （場が育ち、痕跡が積もる過程）そのものを潰してしまう
- 原因調査により、草が見えない真因は**表示の最終段**にあると確定した。
  閾値到達を早める暫定対処自体が不要になった
  （実機ログで270ティック時点に108セルが生成されている実績）

パラメータ自体は残す。既定0なら挙動は従来と同一で、
「平衡状態から始めたい」場面（Demo 6 の不在中進行のテストなど）で使える。

**上の「暫定対処に伴う基準値の変動」の表は無効。**
48シードの基準値は撤回前の値（草食獣 16.11 / 餓死率 1.817 / 絶滅 0/48）に戻る。
踏跡の草の比のテスト閾値も 0.7 → 0.5 に戻した。

## 真因の特定と修正（2026-08-11、同日）

原因A（シーン未再生成）を直した後も草が見えなかった。
**実機ログが真因を確定させた:**

```
草=0セル  ← 6回（約3分間）
[FieldOverlay] 表示: Prey → Death → Trample → None
草=108セル ← None に到達した直後
```

**`FieldOverlayView.Current` の初期値が `Layer.Fear` だった。**
段階4で入れた「場のオーバーレイ表示中は草を隠す」判定が
**起動時から成立**しており、左手Yで6回巡回して `None` に
到達するまで草が永久に描画されない状態だった。

草の生成そのものは正常（270ティック時点で108セル）。
`initialVegetation` の暫定対処が不要だったのはこのため。

### 修正（二重の防御）

1. **`FieldOverlayView.Current` の初期値を `None` に。**
   起動直後は「何も重ねていない」のが正しい初期状態。
2. **非表示判定に「診断モード中」を追加。**
   場のオーバーレイは診断モード限定の機能なので、
   オーバーレイの状態だけで判定すると**通常モードなのに草が消える**
   状態が起こりうる（実際に起きた）。通常モードでは常に草を描く。

### 再発防止テスト

- `Display_GrassIsVisibleInTheStartupState` — 初期値を `Fear` に
  戻すと落ちる
- `Display_GrassIsNotHiddenInNormalMode` — 表示モードの初期値が
  通常モードであることを固定

### 方法論の収穫

**「表示されない」の原因は、生成側ではなく表示の最終段にあることが多い。**
今回は3段階すべて（座標 → シーン配線 → 表示条件）を疑い、
最後の1つが真因だった。値の分布・座標・配線がすべて正常でも
描画されないなら、**残るのは「描くかどうかの判定」しかない**。

この切り分けを可能にしたのは `DrawnCells` をログに出したこと。
パネルにしか無い数値は装着中に取得できない（CLAUDE.md）。

## 既知の不具合（帰宅後に対処）

草が**上面と側面2面のみ**で描かれており、角度によって抜けて見える。
`GrassView` の面生成の網羅性を確認する
（4側面すべてを出すか、ビルボードにするか、
Quest の描画コストとの兼ね合いで決める）。

MR合成の制約（アルファ<1は使えない）があるため、
片面カリングを前提にした省略が入っている可能性がある。

### (b) DebugPanel の FPS 3行がグラフに隠れる — **修正済み（2026-08-11）**

#### 原因: パネルが中心アンカーで、行を増やすと上端がグラフへ伸びる

グラフとパネルは**それぞれ独立にカメラ直下に置かれた World Space Canvas** で、
別々の `localPosition` を持っていた。一方パネルの `sizeDelta.y` は
行が増えるたびに広げてきた（Demo 8 で場の2行を追加して 620px に）。

**中心アンカーなので、高さを増やすと上端が伸びてグラフの下へ潜り込む。**
実測すると重なりは 0.072m = 103px で、テキスト上端の余白12pxを引いて
約91px ≒ **3行ぶん**。隠れていたのは:

1. `USE_SCENE / Planes / RayHit`
2. `Origin / AnchorSaved`
3. `Blocks / Field / **FPS**`

**行を追加するたびに静かに悪化する構造**だったので、位置を数値で調整するだけでは
また再発する。

#### 修正1（構造）: グラフをパネルの子にして上端に張り付ける

`Population Graph` を独立 Canvas からパネル Canvas の子に変え、
`anchorMin = anchorMax = (0.5, 1)`（パネル上端の中央）、
`pivot = (0.5, 0)`（自分の下端を基準に上へ伸びる）、
`anchoredPosition = (0, 10)`（10px の隙間）とした。

**パネルが何行増えてもグラフはその上へ押し出されるだけで、
重なりが構造的に起こらない。**

あわせてパネル全体を下げた（`localPosition.y` −0.25 → **−0.305**）。
スケール 0.0007 で パネル620px = 0.434m、グラフ143px + 隙間10px = 0.107m、
合計 0.541m。0.6m 前方に置くと下端 −0.522m（**−41.0°**）、
上端 +0.019m（**+1.8°**）で、Quest 3 の垂直FOV（±48°）に収まる。

#### 修正2（優先度）: FPS をパネルの先頭行へ

重なりは構造的に解消したが、**最重要の数値を最も読みやすい位置に**は
独立に守る。パネル上端は視野の中心に最も近いので、そこへ移した。
1行目と3行目を入れ替えただけ（`USE_SCENE / Planes / RayHit` が3行目へ）。

#### 検証状況

シーンを再生成し、`Main.unity` の `Population Graph` が
上端アンカー（`m_AnchorMin/Max = (0.5, 1)`、`m_Pivot = (0.5, 0)`、
`m_AnchoredPosition = (0, 10)`）を持つことを確認済み。

**自動テストは無い。** シーンのレイアウト検証は下の (c) の範囲であり、
現時点では Game ビューでの目視（手順は下記）と実機セッションでの確認による。
