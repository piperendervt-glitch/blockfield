## 0. 問い

クラゲの遊泳と操舵は、**方向を計算するコードを一切持たずに**、
興奮性媒質の伝播と減衰だけから成立するか。

この問いは系列1の中心的主張（個体の計算をどこまで場に移せるか）の、
個体内部版である。血縁は軸1（情動の系統発生）の第3段
「内部興奮性媒質」にあたる。

## 2. プロトタイプ検証で判明した設計修正3件

以下は Python プロトタイプ（`excitable_ring.py` / `reentry_map.py` /
`j2_attenuation.py`）で確認した、**実装前に確定させるべき事項**である。
いずれも当初の設計が誤っていた箇所であり、C# 実装で繰り返さない。

### 修正1: 同期更新（ダブルバッファ）が必須

インプレースの逐次更新は、+index 方向への瞬時伝播という**非対称**を生む。
セル i を更新した直後にセル i+1 がその結果を読むため、1ティックで
複数セルを波が進んでしまう。

**規約**: すべての ExcitableField の更新は旧バッファのみを読み、
新バッファへ書く。近傍リストの走査順に依存しないこと
（テストで走査順を反転させても同一結果になることを確認する）。

### 修正2: 振幅減衰 g が必須（初期候補 g = 0.85）

当初設計は「収縮の時間差のみで旋回が出る」としていたが、これは誤り。
時間差だけでは抗力との相互作用により「後発の側が勝つ」力学となり、
**逃避の符号が反転する**。

プロトタイプ実測:

| 減衰 g | 逃避の向き |
|---|---|
| 1.00（減衰なし） | 刺激方向へ向かう（**誤り**） |
| ≤ 0.95 | 刺激と反対方向へ（正しい） |

したがって「ホップ距離に応じた振幅減衰」は装飾ではなく、
**操舵機構の構成要素**である。M-J2b の判定に g の掃引
（符号反転境界の記録）を含める。

### 修正3: R₀ = 14（旧値 4 は誤り）

N = 16 のリングにおける一方向波のリエントリー境界は 13/14 であり、
安全側の 14 を採る。

旧根拠「1周 ≈ 8ステップ」は、**両方向波の対蹠到達時間**との混同だった。
一方向波が1周するには N ステップ要る。境界条件は
「一周時間 > 不応期 + 2」で、N = 16 なら R₀ ≥ 14。

リエントリー（回転波）の**意図的な利用**は J3 の観察項目とする
（禁止事項ではない）。

### 修正4: 振幅は「波が運ぶ状態」であって幾何距離ではない

当初実装（`j2_attenuation.py` / `j2c_quantitative.py`）は、刺激セルからの
ホップ数 `hops` を毎回計算して `g^hops` を掛けていた。これは**幾何距離**であり、
(a) 距離を計算するコードが必要になり、(b) 多重刺激で非物理な結果を出す。

正しい実装（`j2_wave_amplitude.py`）では、振幅を**波が持ち回る状態** A として扱う。
発火セルは `A = max(発火した近傍の A) × g` を受け取り、刺激は A = 1 を注入する。

実測（2026-08-15 再現）:

| 刺激 | 幾何距離モデル | 波振幅モデル | ベクトル平均の予測 |
|---|---|---|---|
| 単一（16方位） | 誤差 0.00° | 誤差 0.00° | — |
| 0° と 90° 同時 | **158.5°** | **225.0°** | 225.0° |
| 0°@t0, 90°@t6 | — | 180.0° | （後発が近い側を強く引く） |

**重ね合わせがベクトル平均として創発するのは波振幅モデルのみ**である。
幾何距離モデルは単一刺激では正しく見えるが、多重刺激で破綻する。

**規約**: C# 実装は波振幅モデルを採る。`ExcitableField` のセルは
興奮度 E・不応期 R に加えて**振幅 A** を持つ。距離を計算するコードを書かない。

## 5. 旋回率経路（本 prereg の新規追加、2026-08-15）

### 5.1 経緯

生理層プロトタイプ（`homeostat.html`）で、受容器を**閾値 θ のみ**に
接続した場合、悪条件の領域からの逃避が起きないことが判明した。

機構: θ が上がると興奮性が下がり、遊泳速度も下がる。
**動きが遅い場所ほど滞在時間が長くなり、密度が上がる**
（走化性で既知の性質）。逃避どころか集積する。

受容器から**旋回率へ**の独立経路を追加して再検定した結果:

| 判定 | 結果 |
|---|---|
| M-K1 経路追加で悪条件から離れる | **合格** 平均深度 0.492 → 0.512、paired d = +0.978、符号一貫 5/6 |
| M-K2 生存を損なわない | **合格** 41.7 → 42.0 |
| 用量反応 | **単調**。係数 0 / .006 / .012 / .024 / .048 / .096 に対し 0.492 / 0.510 / 0.512 / 0.553 / 0.586 / 0.664 |
| 最適値の存在 | 生存は 0.024 超で低下（42.0 → 39.7 → 38.8 → 31.7） |

### 5.2 本 prereg での扱い

**規約**: 受容器から運動への接続は、**速度（θ）と旋回率の2経路を
独立に持つ**。片方だけの実装を禁止する。

**規約**: 旋回率への結合係数は**手で置かず、遺伝子とする**。
用量反応が単調である一方で生存に最適値が存在するため、
値を固定すると「世界定数の設計」ではなく
「個体の戦略パラメータの調整」になり、創発の主張が無効になる。

なお jelly_1 の段階では淘汰が存在しない（環境・餌・繁殖は jelly_2）ため、
**遺伝子化の効果は jelly_1 では測定できない**。jelly_1 では
「2経路が独立に存在し、係数が外部から与えられる形になっている」
ことのみを実装要件とし、値の探索は jelly_2 に送る。

### 5.3 旋回コストの導入順序

現状のモデルでは旋回がコストゼロである。実際には非対称収縮は
前進推力を食うため、旋回率を上げるほど遅くなる。

**このコストは jelly_1 では導入しない。** `jelly_side.html` の
噴流係数の実測から係数を持ち込む形で、jelly_2 で導入する。

**順序を逆にしないこと**: 効くかどうか未検証の機構に、
先に高価な流体を払うことになる。M-K1 で経路の効果が確認できたので、
コストの導入はその次の段である。

## 6. 結果の読み方の限定

### 6.1 jelly_1 は淘汰を含まない

本 prereg の全判定は**機構の検証**であって、適応の測定ではない。
「この機構で泳げる/曲がれる」を示すが、
「この機構が選ばれる」は示さない。後者は jelly_2 の領分である。

### 6.2 M-J2b が不合格だった場合

「時間差 + 減衰では操舵できない」の証明ではない。
g の掃引範囲が不足している可能性、および抗力モデルの
定式化が実際のクラゲと乖離している可能性が残る。
その場合は Pallasdies 型の DNN（周縁の収縮変調）による操舵を
別経路として登録し、2経路の比較実験とする。

### 6.3 プロトタイプとの対応が未検証である

修正3件は Python プロトタイプで確認したものであり、
C# 実装が同じ挙動を示すかは未確認である。
**移植の最初の作業は、プロトタイプの数値の再現**とする
（`flow/` の再現確認と同じ様式）。再現しない場合、
C# 側のバグかプロトタイプ側の環境依存かを切り分けるまで
J1 以降に進まない。

## 8. 却下した設計案と理由

| 案 | 却下理由 |
|---|---|
| 浸漬境界法による流体連成 | リアルタイムに載らない。科学的な核（疎な網でも波は伝わる / 異方性が伝導を構造化 / 二重網による操舵）は軽量に再現できる |
| heading 変数を持たせる | 操舵はペースメーカー位置で決まる。方向を保持した時点で「方向を計算していない」という主張が崩れる |
| 刺激からの幾何距離で振幅を決める | 振幅は波が運ぶ状態である。距離の計算は不要かつ、創発の主張を無効にする |
| 旋回率経路を後回しにする | homeostat の測定により、速度のみの接続では逃避が成立しないことが判明済み |
| 旋回コストを jelly_1 で導入 | 効果が確認された機構に対してコストを足す順序が正しい。逆順は高価 |

として、M-J3a の判定基準を保留した。**これは図の読み違いであり、取り下げる。**

- `1e-15` は y 軸のスケール倍率であって移動距離ではない。同パネルは
  軌跡プロット（x位置 対 y位置）であり、x 軸は 0→500 の実単位、
  y がゼロオーダーである
- したがって同図が示すのは「**横ずれゼロで +x 方向へ約500 進んだ直線遊泳**」で、
  J3a（heading 360.0°、dist 107.3）と向き・性質ともに一致する
- 距離の差も整合する。同図は `fires: {8: 40}`（40回発火）で T=40 なので
  約1,600ステップ。スクリプトは400ステップ＝10回発火で 107.3。
  線形成長なら1,600ステップで約430 であり、図の約500と同じ桁

**M-J3a の判定を確定する**: 単一ペースメーカーから持続遊泳が生じ、
移動距離が時間に対して線形に伸びる。判定閾値は
「t=100 / 200 / 400 の移動距離比が線形から ±15% 以内」かつ
「4方位（cell 0/4/8/12）すべてで期待方向から誤差 < 5°」とする
（プロトタイプ実測は 23.6 / 47.7 / 107.3、誤差 1.8° 以内）。

なお本件は「図の読み違いによる保留」であって測定の誤りではない。
判定基準を確定しないまま実装に進まなかったこと自体は正しい手順であり、
確認により保留を解いた形になる。

## 追記3（2026-08-15）: R₀=14 への統一に伴う再現目標の訂正と、J1 の実装完了

J1 を C# へ移植するにあたり、§7.2 の再現目標に **R₀ 依存のものが
混ざっていた**ことが判明した。実装前に訂正する。

### 1. 「t=12 で消滅」は r0=4 由来である

§7.2 は M-J1a を「t=8 で対蹠（セル8）にて対消滅。t=12 で消滅」と
記載していたが、**後半は `excitable_ring.py` の既定 r0=4 での実測**である。
§7.3-1 は M-J2b について「実測は r0=4 の下で得られている」と注意していたが、
M-J1a の消滅時刻も同じ条件依存を持つことは書かれていなかった。

プロトタイプを r0 だけ変えて実行した実測（コードは変更していない）:

| r0 | 対蹠（セル8）の発火 | 最終発火 | 消滅 |
|---:|---|---:|---:|
| 4 | t=8 | t=8 | **t=12** |
| 14 | t=8 | t=8 | **t=22** |

**対消滅は R₀ に依存しない。** 波は1ステップ1セルで進むので、
伝播と対消滅の幾何は不応期と無関係である。
**消滅時刻だけが 8 + R₀ で決まる。** 終了判定が
「発火なし かつ 全 E&lt;0.01 かつ **全 R==0**」であり、
最後に発火したセルの不応期が抜けるまで待つためである。

**訂正**: R₀=14 における M-J1a の再現目標は以下とする。

| 項目 | 期待値 |
|---|---|
| 対消滅 | t=8、セル8（R₀ 非依存） |
| 消滅 | **t=22** |
| M-J1b の境界 | R₀=13 でリエントリー / 14 で消滅（変更なし） |

r0=4 で再現してから R₀=14 へ切り替える順序は採らない。二度手間であり、
どちらの条件で通ったのかが曖昧になるためである。

### 2. M-J1c の再現方法を変更する

§7.2 は決定論の再現を「ハッシュ `8328cc8b66b40f71` 二回一致」と
記載していたが、この値は **Python のリスト repr の SHA-256** である。
C# で一致させるには Python の文字列表現を再現する必要があり、
移植の正しさの証明にならない。

**変更後の M-J1c の再現方法（2本立て）**:

1. **決定論**: 同一入力から2回走らせて C# 側の ContentHash が一致すること
   （World と同じ FNV-1a 64bit で E・R・A を畳み込む）
2. **移植の正しさ**: **各ステップの発火セル列がプロトタイプの出力と完全一致**すること

2 のほうがハッシュより優れている点がある。**ズレたときにどこでズレたかが分かる。**
ハッシュは一致か不一致かしか教えない。

比較対象のプロトタイプ出力は R₀=14 で取り直した（`excitable_ring.py` の
M-J1c は stim=(3,)・r0=4 の既定値で測っているため、そのままでは使えない）:

```
stim=(0,) R₀=14: t1:[1,15] t2:[2,14] t3:[3,13] t4:[4,12]
                 t5:[5,11] t6:[6,10] t7:[7,9] t8:[8]  → 消滅 t=22
stim=(3,) R₀=14: t1:[2,4] t2:[1,5] t3:[0,6] t4:[7,15]
                 t5:[8,14] t6:[9,13] t7:[10,12] t8:[11] → 消滅 t=22
```

### 3. M-J2b の符号反転境界は測り直しが要る

g の符号反転（g=1.00 で TOWARD、g≤0.95 で AWAY）の実測は
`j2_attenuation.py`（r0=4）で得られたものである。**R₀=14 で境界が
同じ位置に来る保証はない。** J2 に着手する時点で、まず R₀=14 で
g を掃引して境界を測り直すこと。位置が動いていた場合、
それは実装の誤りではなく条件差である。
