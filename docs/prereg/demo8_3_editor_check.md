# Demo 8 第3段 — エディタでの事前確認手順（踏み荒らし）

実機に行く前に PC で確認する手順。
**M1 の本質は「診断モードでなく通常表示で、草の生えない筋が見えること」**なので、
場のオーバーレイを出さない状態での見え方を最初に確認する。

## 前提
- Unity Editor で本プロジェクトを開く（CLI テストと同時実行は不可）
- メニュー `Tools > BlockField > Terrain Preview`

---

## 手順1（最重要）: 場を出さずに「草の生えない筋」が見えるか

これが M1。オーバーレイに頼らず、地表の草の分布だけで道が読めるかを見る。

1. Terrain Preview を開く
2. `Seed = 12345`、`50x50`、起伏スケール 24 のまま **Generate**
3. **「場を表示 (E1 / Demo 8)」のチェックは外したまま**にする
4. **Simulate 100 ticks** を **20回**押す（合計2,000ティック）
   - 500 / 1,000 ティックの時点でも一度見ておくと、道ができていく過程が分かる
5. Scene ビューを**真上視点**にする（右上ギズモの Y 軸をクリック）
6. 緑（草）と黄（花）の立方体の**分布の切れ目**を探す

**期待**: 草が密に生えた領域のあいだを、**草の無い帯**が走っている。
帯は1〜3セル幅で、曲がりながら数十セル続く。
1本道ではなく、太い幹線から枝分かれした**網**に見えるのが正常
（実測: 連結成分6〜13個、最大成分が適性セルの10〜18%、
細長さ3.5〜5.6。恐怖場の6.0〜8.0よりやや塊寄り）。

**見えない場合の切り分け**:
- 草が全体に薄い → 踏み荒らしが強すぎる。植物総数をパネルで確認
  （2,000ティックで 180〜210 が正常）
- 草が一様に濃く切れ目が無い → 踏み跡が立っていない。手順2で場を直接見る
- 帯ではなく点々と抜けている → 通行が分散している。動物数を確認

**スクリーンショット**: `Win + Shift + S` で真上視点の全体を1枚。
手順2の茶色オーバーレイと同じ視点で撮ると、筋の位置が対応しているか比べられる。

---

## 手順2: 踏み荒らし場そのものを見る（答え合わせ）

手順1で見えた筋が、本当に踏み荒らし場と一致しているかを確認する。

1. 手順1の状態から **「場を表示」にチェック**、`表示する場 = Trample`
2. 視点を変えずに見比べる

**期待**: **茶色**の帯が、手順1で草が抜けていた場所に重なる。
茶色が濃いほど通行が多い。

**色の確認**: 緑（植生）・赤（恐怖）・青（獲物）・マゼンタ（死）と
**取り違えないこと**。茶色は彩度が低いので、地形の土色と混ざって
見えにくければ色を変える。

**第2段の教訓は適用済み**: 場ごとの表示基準値（踏み荒らしは0.35）・
平方根変換・濃さの下限を入れてある。灰色に沈んで見えるなら、
色ではなく正規化を疑うこと。

---

## 手順3: 通らなくなれば草が戻るか（τの確認）

踏み荒らしは**可逆**であるべき。永久に草の生えない傷にはしていない。

1. `表示する場 = Trample` のまま、濃い茶色の帯を1つ選んで位置を覚える
2. **Simulate 100 ticks** をさらに数回押しながら、その帯を見続ける

**期待**: 動物が通り続けている帯は濃いまま、通らなくなった帯は
**数百ティックで薄くなって消える**（減衰 0.02 ＝ τ≈50ティック）。
道が動くのが正常。

死の場（τ≈333、消えない）と対照的なので、続けて
`表示する場 = Death` に切り替えて「消えない場」との違いを見ると分かりやすい。

---

## 手順4: 死の場と踏み荒らし場の重なり（M3、記録項目）

事前登録では「分離するはず」と予測したが、**実測は逆で有意に重なった**
（独立なら期待940セルのところ実測1,574セル ＝ 1.67倍）。
動物は歩いた場所で飢え、歩いた場所で捕食されるため。

1. `表示する場 = Death`（マゼンタ）で墓場の位置を覚える
2. `表示する場 = Trample`（茶）に切り替える

**期待**: マゼンタの点の多くが茶色の帯の**上か、すぐ脇**にある。
完全に一致はしないが、無関係な散らばりでもない。

これは「同じセルで草を茂らせる力と消す力が同時に働いている」ことを意味する。
第4段以降の設計判断の入力になるので、見た印象を記録すること。

---

## 手順5: 進化の基盤が動いているか（数値）

重みは個体が持つようになったが、**進化本体は実装していない**ので、
全個体が種ごとの初期値のままであるはず。

Terrain Preview には実機パネルが無いため、実機セッションで見る項目を記す:

- `W(veg/fear/prey) n=NN: 0.80/-1.20/0.20`
  - 草食獣は veg=1.0 / fear=-1.5、狼は prey=1.0。
    表示は全動物の平均なので、種の構成比で値が動く
  - **ばらつき（±）が0でない場合、種構成の違いが原因**。
    同一種内でばらついていたら継承か初期化が壊れている
- `Tramp P: 1.88% vs 14.92% = 0.13   Crush: NNN`
  - 踏み荒らし場の上位25%セルと下位25%セルの植物密度、その比
  - **比は 1.0 ではなく 0.28（対照値）と比べる**。動物は餌のある所を歩き、
    そこで草を食べるので、抑制が無くても踏み跡の草は少ない
- `Fld avg/max ... T:0.069/1.00` — 踏み荒らし場の平均と最大

同じ内容が30秒ごとに `[DebugPanel]` としてログにも出る（CLAUDE.md の規約）。

## 実機で見るときの操作（参考）
- 右手B: 通常 ⇄ 診断モード
- 診断モード中に**左手Y**: マーカー → 植生(緑) → 恐怖(赤) → 獲物(青)
  → 死(マゼンタ) → **踏み荒らし(茶)** → 非表示 を巡回
- **M1 は診断モードに入らずに判定する**。通常表示で草の抜けた筋が
  見えるかどうかが判定基準
