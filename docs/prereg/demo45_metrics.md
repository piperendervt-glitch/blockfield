### G5 の判定範囲
- 棚は Other + 高さヒューリスティックで判定。**M3 の判定対象外**とする。
- 理由: Meta OpenXR の平面ラベル表に棚に相当するラベルが存在せず
  `Other` に落ちるため。M3 の判定条件は「床と机上で異なるバイオーム」
  であり、棚を対象外としても Go 条件は無傷。

#### 変更（2026-08-09、G3 実機セッション後）
変更理由: 診断表示で `Unknown` ラベルの積もり面の正体が判明したため。
実機目視の結果、赤枠（Unknown）は布団の上・ペットボトル・コップ・
棚の小物・散らかった荷物の上面だった。ARPlaneManager が平面化しない
現実の物体である。

- **Unknown ラベルは平面化されない小物・家具・荷物等の上面であり、
  積もり面として採用する**（実機目視で確認）。雪が現実の物の上に
  積もるのと同じ挙動であり、除外は誤りである。
- Unknown のバイオームは高さヒューリスティックで割り当て、
  **M3 の判定対象外**とする（棚と同じ扱い）。
- 面数上限 (MaxSurfacesPerCell=3) とラベル解決範囲 (0.15m) は
  現状で正しいと判断し、調整しない。

### 場の意味論（論点1 の決定: (d) 表面場）
- Demo 4.5 の場は**表面場**（各 (x,z) の最上面に付随）。
  机の下の床面は場を持たない。
- 場のデータ構造は 2D のまま（追加作業ゼロ）。空間の高さ方向の層は
  「**フロア**」と呼ぶ（vision §7 の時間軸の「層」＝τの速さの層と
  区別するため）。
- (b) フロア構造 / (c) 3Dベクトル場 は Demo 6 以降の拡張点として
  roadmap に記録。

### G3 の実装判断（2026-08-09）
- **ログでの計測追い込みは中止し、実機での目視判別に切り替える。**
  面数上限の妥当性、Unknown ラベルの高所面の正体は、G3 の診断表示で
  ユーザーが直接見て判断する（ログの連結成分計測より速く確実）。
- 診断表示（右手Bで切替）:
  - モード0 通常 = 積もった地形のみ
  - モード1 診断 = 積もり面のマーカー（緑=採用した最上面 / 青=2面目以降、
    枠色=ラベル: 白Floor / 橙Table / 紫Other / 赤Unknown / シアンCouch）。
    マーカーが地形に隠れないよう、診断モードでは地形を隠す。
- **積もらせるのは各セルの最上面のみ**（表面場 = 論点1 決定(d) の実装）。
  2面目以降は診断表示にのみ現れる。
- 右手Bボタンの再割り当て: Demo 4 まで箱庭地形の表示トグルだったが、
  部屋地形のモード切替に譲り、箱庭側は左手Xへ移した。
- 箱庭地形 (Demo 1-4, 50x50) は部屋地形と同じ空間を占め観察の邪魔になるため、
  合成完了時に1回だけ自動で隠す（左手Xで戻せる）。
- ブロック種はまだラベルに依存させない（バイオーム対応は G5）。
  層数4以上の柱の表層のみ Stone にして起伏を見やすくする。

### G3 実機セッションの結果と修正（2026-08-09）
- **M1（多層積もり）成立**: 床・机上・棚上に積もり、空中・天井・壁への
  積もりは無し。診断表示で Unknown の正体も判明（上記 G5 の変更を参照）。
- 修正1: 箱庭地形 (Demo 1-4) を**起動時から非表示**にする。
  合成完了後に隠す実装では起動直後の約5秒間だけ見えていた。
  左手Xでの表示は維持。
- 修正2: **部屋地形とマーカーをアンカー原点の配下に置く**。
  ワールド直置きだったため、HMD を外して再装着すると再ローカライズで
  位置がずれていた。RoomScanner が**観測と同じ瞬間**のアンカーポーズを
  記録し、RoomTerrainView がそれで換算してアンカーの子にする。
  - 観測データ (cellY) は整数のまま変換しない。変換するのは**表示配置だけ**
    なので、M4 のリプレイ入力とコンテンツハッシュには影響しない。
  - グリッド軸は観測時のワールド軸（＝部屋の向き）のまま保つ。
    アンカーの回転基底へ座標変換すると、アンカーのヨー角ぶんグリッドが
    部屋に対して斜めになり、AABB も膨らむため採らない。
    再ローカライズの補償には剛体の親子付けで十分である。

### G4/G5 の実装（2026-08-09、第2回セッション後）

**G4 壁の Boundary 化**
- WallFace 平面を XZ 平面上の線分に落とし、観測グリッドへ通行不可セルとして
  ラスタライズする（`WallRasterizer`）。結果はセル単位の bool として
  RoomObservation に載り ContentHash にも入るため、M4 の保証を壊さない。
- 通行不可セルには積もらせず、代わりに Stone を6セル（24cm）積む。
  BlockId は新設せず `origin=Reality` で区別する。
- 徘徊AIは既存の「高低差2以上は移動しない」ルールだけで壁を避ける。
  実測: 壁の表層高さ7 vs 隣接床3 → 高低差4。追加ルールは入れていない。
- 壁の表層は Stone なので適性0 → 壁の上には湧かない。

**G5 平面ラベル→バイオーム**
- Floor → 平原 / Table・Couch → 丘陵 /
  Other・Unknown → 高さヒューリスティック（基準セルYから30セル=1.2m 以上で
  山岳、未満で丘陵）。Ceiling・WallFace は G2 で除外済みなので到達しない。
- 起伏ノイズは全域共通で、バイオームは**振幅だけ**を変える
  （TerrainGenerator と同じ作り。バイオーム境界で地形が不連続にならない）。
  振幅 平原0.35 / 丘陵0.65 / 山岳1.0。
- 実測の層数分布 (81x66, seed=12345):
  - 平原: 1層78.8% 2層21.2%（最大2層）
  - 丘陵: 1層62.6% 2層19.2% 3層18.2%（最大3層）
  - 山岳: 1層54.0% 2層14.8% 3層11.8% 4層19.4%（最大4層）
- 基準セルYは観測内の最低セルY（整数）。worldY は読まない。

**G7 の下ごしらえ**
- `World.CreateFromRoom` を追加。合成済みの部屋グリッドをそのまま
  シムの舞台にする。箱庭 (Demo 1-4) との違いは3点のみで、シムのルールは共通:
  グリッドを生成せず受け取る / XZ範囲は観測グリッド寸法 /
  セルYが負にもなるため表層高さの探索範囲と「面なし」の表現が異なる。
- 「面なし」の柱は番兵 `World.NoSurfaceHeight` を入れる。部屋地形では 0 も
  正当な高さなので、箱庭と同じ「面なし=0」は使えない。
- **未接続**: 実機の TerrainField はまだ箱庭ワールドを回している。
  部屋ワールドへの切り替えは G7 本体で行う（下記の確認結果を参照）。

### 変更（2026-08-09、第3回セッション後）

変更理由: 第3回セッションで M3（バイオーム）合格。一方で壁セルに切れ目が
見つかったため M2 の成立条件を補強する。あわせて雪の表現をスコープに加える。

**G4 の補強: 外周の無条件 Boundary 化**
- WallFace 平面が実測4枚しかなく、窓・ドア・家具の陰・平面化されない壁で
  切れ目が生じた。M2 の目的は「動物が部屋の外に漏れないこと」なので、
  観測グリッドの**最外周セルを無条件に Boundary**（origin=Reality）にする。
- 平面由来の壁セルは維持する（部屋内部の仕切り壁に効く）。
- 天井側は不要（動物は飛ばない）。
- 実測 (81x66): 外周290セル、外周と隣接床の高低差4（2以上で通行不可）。
  300ティック後に外周セル上の個体は0。

**G5 に雪の表現を追加**
- 山岳バイオーム（Other/Unknown で床から1.2m以上）の表層1層を Snow とする。
  BlockId に Snow を追加（白）。Demo 1 の「厚い柱の表層は Stone」と同じ仕組み。
- **ユーザー要望による見た目の改善であり、M3 の判定基準は変更しない。**
- 付随する判断: 適性場の「湧ける表層」に Snow を含める。Grass のみのままだと
  山岳＝棚の上に一切湧かなくなり、表面場の意味論（各(x,z)の最上面が場を持つ）
  と矛盾するため。Stone（壁・厚い柱の頂上）は従来どおり対象外。
  箱庭 (Demo 1-4) には Snow が存在しないので既存のハッシュは不変
  （検証済み: 箱庭10ティック後 CB7E32FC268C0AFB が変更前後で一致）。

**G7: 生態系を部屋地形へ接続（実機接続まで完了）**
- TerrainField を2モード化した。roomBuilder がある場合は**箱庭グリッド
  (50x50) を生成せず**、観測の到着を待って `World.CreateFromRoom` で
  部屋地形の上に World を作る。
- チャンク・エンティティ・設置破壊の照準がすべて同じ地形ルートと
  同じセル→ローカル写像を共有するようにした（TerrainField.CellToLocal）。
  部屋モードのルートは観測時のアンカーポーズ基準。
- 観測の EventLog への記録は TerrainField が行う（World がその観測から
  作られるため、生成前には記録できない）。
- 実測の適性・スポーン分布（床81x66＋机20x20＋棚8x8、300ティック）:
  表層 Snow=64 / Grass=4992 / Stone=290、
  個体62（植物42・動物20）の帯別内訳は 床帯57 / 机帯5 / 棚帯0。
  棚は面積比1.2%と小さく5分程度では湧きにくい。**面積比におおむね比例**
  しており、表面場の意味論どおりに分散している。
- 左手Xの箱庭表示トグルは廃止（箱庭グリッドそのものが無くなったため）。
  Aボタンは積もり方のシード巡回として残す。

### M4 の保証範囲（論点2 の決定: (iii) 二本立て）
- **M4 が保証するのは「同一のヒット高さ列から地形合成以降が
  同一 ContentHash を生む」こと。**
- 生メッシュのアーカイブは**反復用資材であり M4 の保証対象外**。
  アーカイブからリプレイしても、レイキャスト（浮動小数点の幾何演算）が
  再実行されるため bit-exact は保証されない。
- ヒット高さは**セル単位の整数**で記録する。リプレイ経路から
  浮動小数点の幾何演算を構造的に排除するため。
