# Demo 8.5 — エディタでの事前確認手順（草の表示）

実機に行く前に PC で「草の高さで場の値が読めるか」を目視する手順。
M5 の本判定は実機セッション（帰宅後）で行うが、
**表示が成立しているかどうかは PC だけで確認できる**。

## 前提
- Unity Editor で本プロジェクトを開く（CLI テストと同時実行は不可）
- メニュー `Tools > BlockField > Terrain Preview`

## 手順1: 草が高さ3段階で描かれているか

1. `Seed = 12345`、`50x50`、起伏スケール 24 のまま **Generate**
2. **Simulate 100 ticks** を **15回**押す（合計1,500ティック）
   - ロジスティック成長は立ち上がりが緩やかで、400ティックでは
     まだ濃いセルが1つも無い（実測: 400tで平均0.115、1,500tで0.246）
3. Scene ビューを**斜め45度**にする（右上ギズモの角をクリック）

**期待**: 地表に緑の直方体が生え、**高さが3種類**ある。

| 植生場の値 | 高さ（ブロック比） | 見え方 | 実測のセル数 |
|---|---:|---|---:|
| 0.24 以上 | 0.75 | 高い。明るい緑 | 約100 |
| 0.20 〜 0.24 | 0.45 | 中くらい | 約270 |
| 0.16 〜 0.20 | 0.20 | 低い。やや暗い緑 | 約310 |
| 0.16 未満 | — | **描かれない**（地面が見える） | 残り |

合計で適性2,225セルのうち約680セルに草が出る。

**この閾値は実測分布から決めてある。** 事前登録の目安（0.2/0.5/0.8）は
使えなかった — 植生場はロジスティック成長の釣り合い点で頭打ちになり
**最大でも 0.345** にしかならず、0.5 と 0.8 は一度も到達しないため
上2段が永久に使われなかった（詳細は `demo85_metrics.md` の追記4）。

**ちらつきは正常**。閾値の間隔が狭い（0.16 / 0.20 / 0.24）ので、
閾値付近のセルはティックごとに高さが変わる。
これは「値が閾値付近にある」という情報そのものであり、
ヒステリシスで隠していない（事前登録の方針）。

### 草が1つも見えない場合

**過去に2つの原因で全く見えなかったことがある。** 再発したらこの順で疑う。

1. **閾値が分布と噛み合っていない** — `表示する場 = Vegetation` にして
   オーバーレイが出るのに草が出ないなら、これ。
   分位点を測り直して閾値を決め直す
2. **草が地中に埋まっている** — Scene ビューで `Grass` オブジェクトが
   存在するのに見えないなら、これ。地表は `surfaceY × ブロックサイズ` にあり、
   立方体メッシュは原点中心なので高さの半分だけ上げる必要がある

## 手順2: 場の値と高さが対応しているか（答え合わせ）

1. 手順1の状態から **「場を表示 (E1 / Demo 8)」にチェック**、
   `表示する場 = Vegetation`
2. 真上から見下ろす（右上ギズモの Y 軸）

**期待**: **シアン（水色）**のオーバーレイが濃い場所ほど、
手順1で見た草が高かった場所と一致する。

**チェックを入れると草は消える。** 草の房（幅0.55・高さ最大0.75ブロック）が
オーバーレイの平板（幅0.9）の中央を覆い、真上から見ると場が細い枠にしか
見えなくなるため、オーバーレイ表示中は草を描かない。
位置の対応は「手順1で覚えた場所」と見比べる形になる。

### 場の色（凡例）

| 場 | 色 | 備考 |
|---|---|---|
| **植生** | **シアン** | 意味は緑だが、**地形の草ブロックと同系色で図と地が分離しない**ためシアンにしてある |
| 恐怖 | 赤 | |
| 獲物 | 青 | |
| 死 | マゼンタ | |
| 踏み荒らし | 茶 | |

植生場だけ意味と色が食い違うのは、**地形と色相が衝突するのが植生場だけ**だから。
他の4場は地形の緑・白・灰・茶と離れており、そのまま明確に見える。

**濃淡がはっきり出ること。** 表示基準値を実測の90%点（0.21）に合わせてあるので、
10%点のセルで濃さ0.55、90%点で1.00 になる。
**全面が均一に見えたら表示基準値が分布と合っていない**
（旧基準 0.90 のときは全域が 0.27〜0.49 に潰れて均一な緑に見えた）。
場のパラメータを変えた直後にこれが起きやすい。

## 手順3: 草が食べられて減るか

1. 「場を表示」を外し、斜め視点で動物（白＝羊 / ピンク＝豚）を探す
2. **Simulate 10 ticks** を数回押し、動物の周りの草を見る

**期待**: 動物が通った後のセルの草が**低くなる**か消える。
時間が経つと戻る（成長 0.028 に対し摂食は一口 0.5）。

**注意**: 1頭が1ティックに食べるのは0.2程度で、草の高さが1段階
下がるとは限らない。数ティック見続ける必要がある。

## 手順4: けもの道が草の高さで見えるか

1. **Simulate 100 ticks** をさらに10回（合計2,500ティック程度）
2. 真上から見下ろす

**期待**: 草の**低い帯**または**草の無い帯**が網状に走っている。
これは Demo 8 第3段の踏み荒らしが植生場を削った跡で、
草が場になったことで**通常表示のまま**見えるようになった。

`表示する場 = Trample`（茶）に切り替えて、帯の位置が一致するか確認する。

### けもの道と「単に草が薄い場所」を区別する

草が低いだけでは、けもの道なのか元々植生場が低いのかが分からない。
**3枚を順に切り替えて重ね読みする**:

1. `Vegetation`（緑）— 草が薄い場所はどこか
2. `Trample`（茶）— 通行が多い場所はどこか
3. 両方が重なっていれば**けもの道**。緑だけが薄くて茶が無ければ
   単に草が育っていない場所（適性が低い・端の方など）

けもの道は**細長い帯**として現れる（実測の細長さ 3.5〜5.6）。
塊状に薄いだけなら踏み荒らしではない。

## 手順5: 個体数の読み方

パネルの表示が変わっている:

- `Grass: NNN` — **植生場の全セルの値の合計**。
  「草のあるセル数」でも「植物の本数」でもない。
  1セルの上限が 1.0 なので理論上の最大はセル数（50×50 なら 2,500）。
  実測 300 前後（適性2,225セル × 平均0.135）。
  移行前の `PlantCount`（本数、実測155前後）とは**数え方が違うので
  直接比較してはいけない**
- `Sheep` / `Pigs` / `Wolves` — 従来どおり

実機パネルでは `Tick: N  Grass: NNN  Animals: N  Wolves: N` と出る。
同じ内容が30秒ごとにログにも出る（CLAUDE.md の規約）。

## 実機セッションで判定すること（帰宅後）

- **M5**: 草の高さで場の値が読めるか（パススルー越しに3段階が区別できるか）
- **M6**: 場5枚＋草のメッシュで72FPSを維持できるか

**セッション前に必ず build_quest.ps1 → deploy.ps1 を実行する**（CLAUDE.md）。

## 表示の更新コストについて（実装メモ）

草のメッシュは**1秒に1回**まとめて組み直す（`GrassView`）。
場は 1Hz でしか動かないので毎フレーム組み直す必要がない。
セルごとに GameObject を作らず**1枚のメッシュ**にまとめており、
移行前に約155個あった植物の GameObject は0になった。

エディタプレビューだけは GameObject をセルごとに作っている
（Simulate を押したときだけ走るので、エディタ用途では十分軽い）。
