# Demo 8.5 事前登録 — 植物の場化

登録日: 2026-08-10 / 対象タグ: demo-8.5.x
方針: roadmap Demo 8.5 に対応。押し付け候補リストの第1項。
植物を Entity ではなく植生場の値そのものとして扱い、個体側の
処理と管理対象を削減する。本プロジェクトの目的（個体の処理負荷を
下げる）に直接対応する最初の本格的な実装。

## スコープ
- K1: 植物 Entity の廃止。植生場の値が草の存在を表す
- K2: 摂食の変更 — そのセルの植生場を減らし、減らした量に比例して
  hunger を回復する（従来は「植物1個を食べて hunger=0」の離散処理）
- K3: 表示の変更 — 場の値から直接描く。値に応じて草の高さ3段階
  （目安: 0.2で低い / 0.5で中 / 0.8で高い）。ちらつき対策
  （ヒステリシス）は行わない。花（Flower）は廃止し GrassTuft に統合
- K4: 影響を受ける既存機構の調整 — 植物のスポーン、占有索引、
  ContentHash、踏み荒らしによる踏み潰し、死の場の養分効果、
  草食獣の摂食判定
- K5: 判定

## 表示についての方針（記録）
表示は「処理内容を人間が確認できる」ことが要件であり、美観は
目的ではない。閾値付近のちらつきは、値が閾値付近にあるという
情報として機能するため許容する。

## メトリクス
- M1（負荷削減・主軸）: エンティティ数と1ティックあたりの
  処理時間の削減を実測。植物 Entity 廃止前後で比較
  （現状の植物上限は200、動物は密度基準）
- M2（等価性）: 48シードで生態系の挙動が同等であること。
  比較項目は個体数推移（草食獣・狼）、餓死率、捕食率、
  絶滅率。植物は「本数」から「場の総量」に指標が変わるため、
  適性セルあたりの植生場の平均で比較する
- M3（決定論）: ContentHash 一致（植生場を含む。植物 Entity が
  ハッシュ対象から外れるため、移行前後でのハッシュ一致は
  期待できない。同一実装内での再現性を検証する）
- M4（安定性）: Demo 8 第2段で確立した基準（草食獣ギルド≧1 かつ
  狼≧1 かつ 植生場の総量>0、時間を通した最小値）を48シードで維持
- M5（表示・記録のみ）: 草の高さで場の値が読めるか。実機で目視
- M6（性能・記録のみ）: 実機で72FPS維持

## Go/No-Go
- Go条件: M1 かつ M2 かつ M3 かつ M4
- M5・M6 は記録項目（実機確認は帰宅後）

## M2 の判定基準（等価性をどう測るか）
「同等」の定義を事前に固定する:
- 草食獣・狼の平均個体数: 移行前の ±20% 以内
- 餓死率・捕食率（1個体1000ティックあたり）: 移行前の ±30% 以内
- 絶滅率（M4 の基準に対する違反シード数）: 移行前と同等またはそれ以下
- 上記を48シードの平均で判定する
移行前の基準値は、実装着手前に SimRunner で計測して本ファイルに
記録すること

## 移行前の基準値（2026-08-10 計測、48シード×3000t）

計測コマンド:

```
dotnet run -c Release --project tools/SimRunner -- --seeds 48 --ticks 3000 --out runs/demo85_baseline
dotnet run -c Release --project tools/SimRunner -- --seeds 5 --ticks 3000 --parallel 1 --images 0 --out runs/demo85_timing
```

### 生態系の基準値と M2 の合格範囲

| 指標 | 基準値 | 許容 | **合格範囲** |
|---|---:|---|---|
| 草食獣（Sheep+Pig）の平均個体数 | **18.77** | ±20% | **15.02 〜 22.53** |
| 狼の平均個体数 | **3.67** | ±20% | **2.93 〜 4.40** |
| 餓死率（1個体1000ティックあたり） | **2.126** | ±30% | **1.488 〜 2.764** |
| 捕食率（1個体1000ティックあたり） | **0.702** | ±30% | **0.492 〜 0.913** |
| 絶滅率（安定条件違反シード数 / 48） | **2 / 48** | 同等以下 | **≦ 2 / 48** |

**「平均個体数」の定義**: warmup（300ティック）以降の**毎ティックの平均**を
48シードで平均したもの。最終時点の1点は揺れが大きく基準にならないため使わない。
餓死率・捕食率の分母は延べ生存動物ティック数（個体数に比例して増える
絶対数では実装の前後を比べられないため）。

絶滅の内訳: 草食ギルド 0/48、狼 2/48、植物 0/48。
狼の 2/48 は生態系そのものの性質であり退行ではない
（死の場も踏み荒らしも切った状態でも 3/48 起きる。Demo 8 第2段の計測）。

### 植物の指標（移行で置き換わる）

| 指標 | 基準値 | 移行後の扱い |
|---|---:|---|
| 植物の平均本数（1ティックあたり） | **155.06** | **消滅**（Entity が無くなるため）。参考値 |
| 植物の本数（最終時点の平均） | 207.96 | 同上。参考値 |
| **適性セルあたりの植生場の平均** | **0.2160** | **これが移行後の比較対象** |

植生場は移行の前後で意味が変わる（現在は「植物の周囲に立つ痕跡」、
移行後は「草そのもの」）。したがって **0.2160 という値の一致を
求めるのは誤り**であり、M2 の合否は上表の草食獣・狼・餓死・捕食で
判定する。本値は「草の総量が桁で変わっていないか」を見る参考指標として
記録する。

### M1（負荷削減）の基準値

| 指標 | 基準値 |
|---|---:|
| エンティティ数の平均（1ティックあたり） | **177.50** |
| 　うち植物 | **155.06**（87.4%） |
| 　うち動物（草食獣＋狼） | **22.44**（12.6%） |
| 1000ティックあたりの処理時間（単一スレッド） | **268.8 ms** |
| （参考）同・14並列時 | 491.4 ms |

**エンティティの87.4%が植物である。** K1 が成立すれば、
管理対象のエンティティは 177.50 → 約22（動物のみ）に減る見込み。
これが Demo 8.5 の主眼である。

処理時間は単一スレッドの値を基準とする。並列時の値（491.4 ms）は
コア間の競合を含むため、実行時の並列度に依存して変わり、
実装の前後を比べる基準にならない。

## M1 の測定方法（移行後も同じ方法で測ること）

### エンティティ数
**warmup（300ティック）以降の毎ティックの平均**。最終時点の1点は
揺れが大きく基準にならないため使わない。
`world.Entities.Count` を毎ティック加算して平均する。

測定コード: `tools/SimRunner/Runner.cs` の `RunOne`
（`entitySum` / `MeanEntitiesPerTick`）。
植物・動物の内訳は `MeanPlantsPerTick` / `MeanHerbivoresPerTick` +
`MeanWolvesPerTick`。

### 処理時間
**ティックループのみ**を測る。以下は含めない:
- ワールド生成（`Runner.MakeWorld`）
- 走行後の集計（`Collect`。場の全走査を含むため重い）
- 画像生成・ファイル出力（`report.html` / PNG / CSV）

測定コード: 同 `RunOne` の `simWatch`。ループ内の集計は個体数
カウンタの読み出し（O(1)）だけに絞ってあり、場の走査のような
重い処理は入れていない（時間の汚染を避けるため）。

**必ず `--parallel 1` で測る。** 並列実行はコア間の競合で
1ランあたりの時間が伸び、並列度・同時実行数・他プロセスの負荷に
依存する。移行前後で条件を揃えるため、単一スレッドの値を基準とする。

出力は `summary.json` の `msPer1000Ticks`（1000ティックあたりの
ミリ秒。ティック数の違う実行どうしを比べられるようにするため）。

## リスクと想定される論点（実装前の記録）
- 摂食が連続量になることで、hunger の回復が中途半端になり
  餓死が増える可能性。K2 の減少量と回復係数の設計が要
- 植生場の「床値」（現在スポーン抽選で使用）の扱い。
  場そのものが草になるため、床値の意味が変わる
- 踏み潰し（trampleCrushChance）は「植物 Entity を消す」処理
  だったため、「場の値を減らす」に置き換わる
- 死の場の養分効果は「スポーン重みに (1+k×death) を掛ける」
  だったため、「植生場の成長率に掛ける」等に置き換わる
- 上記の置き換えで生態系のバランスが変わりうる。M2 が
  不合格の場合、パラメータ調整で吸収するか、機構を見直すかを
  判断する

## スコープ外とした機能（2026-08-10 判断）

**Demo 4 M1d の「植物の独立破壊」は本 Demo により廃止する。**

M1d の目的は「プレイヤー干渉が生態系に届くこと」の実証であり、
その実証は完了している。草が場になった以上「1本を狙って壊す」は
概念的に成立せず、無理に残すと「木は個体、草は場」という境界が
濁る（Demo 9 の前提）。プレイヤー干渉は地形の設置・破壊として残るため、
環境を変えて生態系に影響する形になる。思想としてはむしろ適切である。

`SimEventType.PlayerBreakPlant` は**列挙子として残す**。過去のイベントログを
リプレイしたときに未知のイベント種別で落ちるのを避けるため。
適用時は植生場を減らすだけの処理になる。
`docs/prereg/demo4_checklist.md` にも同じ注記を入れた。

プレイヤーが草に干渉する機能が必要になれば、場の値を減らす新機構として
再実装する。

## 実装の段階（2026-08-10 決定）

各段階でコンパイルとテストが通る状態を保つため、
**「場を先に作り、Entity を最後に外す」**順で進める。
リスクの高い3箇所（摂食の連続化・踏み潰しと養分の置換・占有索引の副作用）を
別々の段階に分離してあるのは、同時に変えると M2 が不合格になったときに
原因を特定できないため。

| 段階 | 内容 | リスク |
|---|---|---|
| 0 | `ScalarField.Consume` とパラメータの追加（未配線） | なし |
| 1 | 摂食を場から行う（K2）。植物 Entity はまだ残す | 中 |
| 2 | 踏み潰しと死の場の養分効果を場に移す | **最大** |
| 3 | 植物 Entity の廃止（K1）。占有索引から除外 | 大 |
| 4 | 表示（K3） | なし（SimCore に触れない） |
| 5 | 判定 | — |

段階1〜2で植物 Entity をあえて残すのは、場と Entity が二重にある
冗長な中間状態を許容する代わりに、各段階で「テストが通る・SimRunner で
計測できる」状態を維持するため。

## 移行期間中の決定論の監視（2026-08-10 決定）

段階1以降はハッシュが変わるため、夜間バッチの `--compare` が
「決定論の破れ」を報告し続ける。そのままでは**本物の破れを見逃す**。

対処として、**実行時の git HEAD を `summary.json` に記録し、
差分レポートで区別する**ようにした。

| ハッシュ | コミット | 表示 |
|---|---|---|
| 不一致 | 変わっている | 橙の警告「実装も変わっています」 |
| 不一致 | **同一** | **赤の警報「決定論が破れています」** |
| 不一致 | 取得不可 | 区別できない旨を明記した警告 |

固定の比較対象ディレクトリを置く案より、こちらを採った。
基準の貼り直しという運用が要らず、**判断の材料（コードが変わったか）を
機械が持つ**ため、人間が「これは想定内の不一致だったか」を
思い出す必要がなくなる。

# 追記1 (2026-08-10): 段階1（摂食の場化）

## 変更1: `grazeThreshold` を 0.05 → 0.70 に変更

**0.70 は段階1〜2の中間状態専用の暫定値である。**

中間状態では植生場が「草そのもの」ではなく**植物の周囲ににじんだ痕跡**
であるため、低い閾値では餌場が植物の 7.6倍（閾値0.05時、1,681セル対
220本）に広がり、餓死率が基準の 1/4.4 に低下した。

| 閾値 | 食べられるセル | 植物数 | 倍率 |
|---:|---:|---:|---:|
| 0.05 | 1,681 | 220 | 7.63x |
| 0.20 | 1,039 | 220 | 4.72x |
| 0.50 | 465 | 220 | 2.11x |
| **0.70** | **275** | **220** | **1.25x** |

移行前の餌場は実質的に **veg ≧ 0.76 のセル**（植物のあるセルの植生場は
0.76〜0.98、中央値 0.939）であり、閾値0.70 はこれとほぼ一致する。

**段階3で植生場が「草そのもの」になった時点で、この閾値は 0.05 付近に
戻す必要がある。**

### 副産物: 暗黙のパラメータが可視化された

**移行前の餌場が veg ≧ 0.76 だったことは、移行前の実装では明示されて
いなかった暗黙のパラメータであり、本計測で初めて可視化された。**

移行前は「植物 Entity のあるセル」を餌場としており、そのセルの植生場が
どの範囲にあるかは誰も指定していなかった。植物が毎ティック 0.3 を書き、
減衰 0.02 で釣り合った結果として 0.76〜0.98 に落ち着いていただけである。
場に移して初めて、この値を明示的に選ぶ必要が生じた。

## 変更2: 中間状態では、草を食んだセルの植物 Entity を取り除く

段階1では植物 Entity がまだ存在し、`UpdateVegetation` が毎ティック
植生場へ書き込む。食べたセルに植物が残っていると翌ティックに場が
`vegetationDeposit`（0.3）で回復し、「食べても減らない」無限の餌場になる。

そこで**草を食んだセルに植物 Entity がいれば取り除く**。
植物の増減（スポーン・上限・除去）は移行前と同じ経済のまま保たれ、
**段階1で変わる変数は hunger の回復のしかただけ**になる。

## `alreadyEaten` の廃止

場からの減算は「同じ植物を2頭が食べる」問題を構造的に解消する。
2頭目は1頭目の食べ残しを得るだけで破綻しない。
個体側が持ち回っていた HashSet がひとつ消えた（M1 に寄与）。
