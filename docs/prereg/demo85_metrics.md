# Demo 8.5 事前登録 — 植物の場化

登録日: 2026-08-10 / 対象タグ: demo-8.5.x
方針: roadmap Demo 8.5 に対応。押し付け候補リストの第1項。
植物を Entity ではなく植生場の値そのものとして扱い、個体側の
処理と管理対象を削減する。本プロジェクトの目的（個体の処理負荷を
下げる）に直接対応する最初の本格的な実装。

## スコープ
- K1: 植物 Entity の廃止。植生場の値が草の存在を表す
- K2: 摂食の変更 — そのセルの植生場を減らし、減らした量に比例して
  hunger を回復する（従来は「植物1個を食べて hunger=0」の離散処理）
- K3: 表示の変更 — 場の値から直接描く。値に応じて草の高さ3段階
  （目安: 0.2で低い / 0.5で中 / 0.8で高い）。ちらつき対策
  （ヒステリシス）は行わない。花（Flower）は廃止し GrassTuft に統合
- K4: 影響を受ける既存機構の調整 — 植物のスポーン、占有索引、
  ContentHash、踏み荒らしによる踏み潰し、死の場の養分効果、
  草食獣の摂食判定
- K5: 判定

## 表示についての方針（記録）
表示は「処理内容を人間が確認できる」ことが要件であり、美観は
目的ではない。閾値付近のちらつきは、値が閾値付近にあるという
情報として機能するため許容する。

## メトリクス
- M1（負荷削減・主軸）: エンティティ数と1ティックあたりの
  処理時間の削減を実測。植物 Entity 廃止前後で比較
  （現状の植物上限は200、動物は密度基準）
- M2（等価性）: 48シードで生態系の挙動が同等であること。
  比較項目は個体数推移（草食獣・狼）、餓死率、捕食率、
  絶滅率。植物は「本数」から「場の総量」に指標が変わるため、
  適性セルあたりの植生場の平均で比較する
- M3（決定論）: ContentHash 一致（植生場を含む。植物 Entity が
  ハッシュ対象から外れるため、移行前後でのハッシュ一致は
  期待できない。同一実装内での再現性を検証する）
- M4（安定性）: Demo 8 第2段で確立した基準（草食獣ギルド≧1 かつ
  狼≧1 かつ 植生場の総量>0、時間を通した最小値）を48シードで維持
- M5（表示・記録のみ）: 草の高さで場の値が読めるか。実機で目視
- M6（性能・記録のみ）: 実機で72FPS維持

## Go/No-Go
- Go条件: M1 かつ M2 かつ M3 かつ M4
- M5・M6 は記録項目（実機確認は帰宅後）

## M2 の判定基準（等価性をどう測るか）
「同等」の定義を事前に固定する:
- 草食獣・狼の平均個体数: 移行前の ±20% 以内
- 餓死率・捕食率（1個体1000ティックあたり）: 移行前の ±30% 以内
- 絶滅率（M4 の基準に対する違反シード数）: 移行前と同等またはそれ以下
- 上記を48シードの平均で判定する
移行前の基準値は、実装着手前に SimRunner で計測して本ファイルに
記録すること

## リスクと想定される論点（実装前の記録）
- 摂食が連続量になることで、hunger の回復が中途半端になり
  餓死が増える可能性。K2 の減少量と回復係数の設計が要
- 植生場の「床値」（現在スポーン抽選で使用）の扱い。
  場そのものが草になるため、床値の意味が変わる
- 踏み潰し（trampleCrushChance）は「植物 Entity を消す」処理
  だったため、「場の値を減らす」に置き換わる
- 死の場の養分効果は「スポーン重みに (1+k×death) を掛ける」
  だったため、「植生場の成長率に掛ける」等に置き換わる
- 上記の置き換えで生態系のバランスが変わりうる。M2 が
  不合格の場合、パラメータ調整で吸収するか、機構を見直すかを
  判断する
