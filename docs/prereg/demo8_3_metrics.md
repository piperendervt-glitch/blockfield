# 追記1 (2026-08-09): 実装中の判断と、ヘッドレス事前検証の結果

## 判断1: 既存植物の踏み潰しを**実装した**

事前登録で「実装するか判断して理由を報告」とした項目。**実装した。**

スポーン抑制だけだと「新しく生えない」だけになり、既にある草が消えるのを
草食獣に食われるまで待つことになる。けもの道が見えるまでの時間が
M1（実機5分セッションでの目視）に対して長すぎる。
踏み潰しを入れると通行開始から数十ティックで筋が見え始める。
「歩いたら草が消える」は直感にも合う。

閾値は 0.35 → **0.10** に下げた。3,000ティック時点の踏み荒らし場の分布
（seed 12345、適性2,225セル）:

| 統計 | 値 |
|---|---|
| 中央値 | 0.024 |
| 75%点 | 0.091 |
| 90%点 | 0.257 |
| 99%点 | 0.632 |
| 最大 | 1.000 |

| 閾値 | 該当セル | 割合 |
|---|---|---|
| 0.35 | 139 | 6.2% |
| 0.20 | 278 | 12.5% |
| **0.10** | **523** | **23.5%** |

0.35 では3シード×3,000ティックで踏み潰しが **15件**しか起きず、機構として
働いていなかった。0.10（＝「通行のある域」）にすると375件になり、
**植物総数は 205 のまま変わらない**（生態系を壊さずに可視化だけが速くなる）。
0.05／確率0.05 まで下げると1,087件になるが植物が 205→98 に半減するので採らない。

## 判断2: 重みは配列でなく**構造体**、場の一覧は辞書でなく固定メンバ

事前登録では「場の一覧は World.Fields から取り、重みの順序を場の名前順で固定」
としたが、実装は**固定メンバの構造体**にした。理由2点。

1. **配列だと繁殖で親子が同じ実体を共有する。** `Entity` は構造体でリストに
   値で入るため、`float[]` にすると構造体をコピーしても配列参照は共有される。
   「親の重みをコピー」したつもりが同じ配列を指し、変異を入れた瞬間に
   親子で値が連動する。構造体なら値でコピーされる。
2. **辞書引きは毎ティック走る。** 1個体1ティックあたり4方向 × 場の数だけ
   辞書アクセスが発生する。Quest で72FPSを保つ必要がある。

代わりに、**メンバの並びが `World.Fields` の名前昇順と一致すること**を
EditMode テスト (`M6_WeightOrderMatchesFieldNameOrder`) で固定した。
場を追加するときは構造体にメンバを1つ足すだけで、行動コードは触らずに済む。

## M6（進化基盤の等価性）— **合格。ビット単位で一致**

移管前のコミット `051e0a2` から SimCore を取り出して基線を作り、
**48シード × 1,000ティック**の個体状態シグネチャ
（id / kind / cell / facing / hunger / breedCooldown を毎ティック畳み込み）を
突き合わせた。移管後は踏み荒らしを無効化（deposit 0 / 抑制 0 / 踏み潰し 0）。

**結果: 48シードすべて完全一致。**

一致する理由は演算の性質から説明できる。移管後のスコアは
`Σ(重み × 場の値)` を名前昇順に足す形だが、
- 重み0の項は `0 × 値 = 0`
- `x + 0` は IEEE754 で厳密
- `(-a) × b == -(a × b)`、`x - y == x + (-y)`、加算は可換

なので `w_veg × 植生 − w_fear × 恐怖` とビット単位で同一になる。

## M2（踏み荒らしの定量）— **合格**

48シード × 3,000ティック、踏み荒らし場の上位25%セルと下位25%セルの植物密度:

| 条件 | 上位25% | 下位25% | 比 |
|---|---|---|---|
| 踏み荒らし有効 | 0.0188 | 0.1492 | **0.126** |
| 対照（deposit はするが植物に影響しない） | 0.0340 | 0.1204 | **0.282** |

踏み跡の濃いセルの植物密度は静かなセルの **1/8**。事前登録の
「高いセルの植物密度が低いセルより有意に低い」は明確に成立。

**ただし内訳の注意**: 対照でも比は 0.282 しかない。
動物は餌のある所を歩き、そこで草を**食べる**ので、抑制を切っても
踏み跡のセルは草が少ない。抑制・踏み潰しの寄与はそこからさらに
半分程度にすることであり、全部が踏み荒らしの効果ではない。

**対照との差は48シードでも揺れる**（有効/対照）:

| シード数 | 2,000t | 3,000t | 5,000t |
|---|---|---|---|
| 3 | 0.99 | 0.63 | 0.80 |
| 12 | 0.57 | 0.36 | 0.97 |
| **48** | **0.65** | **0.45** | **0.75** |

48シードでは3つの時点すべてで1未満（効果あり）だが、12シード以下では
符号が消える組み合わせが出る。EditMode テストでは対照比較を主張せず、
どの規模でも頑健な「踏み跡の草は明らかに少ない」だけを固定した。

## M5（生態系の安定）— **合格。むしろ改善**

|---|---|---|---|---|
| 踏み荒らし有効 | **0/48** | **2/48** | **0/48** | 128 |

## 掃引の運用（記録）

本段の検証で、シード数×ティック数×条件の3×3格子（126ラン）を回して
10分を超え、実行を中断した。1シードあたりは 238ms/1,000ティックで、
48シード×3,000ティックは1条件34秒でしかない。
**問題は標本数ではなく条件数の掛け算**だった。
`CLAUDE.md` に「掃引は必要最小限の格子に絞るか、並列化してから行う」を追記した。

なお pre-push ゲート（`.githooks/pre-push`）は EditMode テストのみで、
48シード検証は含まない。EditMode 全体の実測は101秒。

## M3（死の場との空間関係）— **予測が外れた。記録**

事前登録では「通行の多い場所と死ぬ場所は必ずしも一致しないため
**分離するはず**」と予測したが、**逆に有意に重なった**。

48シード合算（適性セルのみ、踏み跡は 0.10 以上、墓場は死の場 0.02 以上）:

| | セル数 |
|---|---|
| 墓場かつ踏み跡 | 1,574 |
| 踏み跡のみ | 20,046 |
| 墓場のみ | 3,413 |

独立なら重なりの期待値は 940。実測 1,574 で **1.67倍**。
墓場セルの踏み荒らし場の平均は 0.1136 で全体平均 0.0691 の **1.64倍**。

**予測が外れた理由**: 動物は歩いた場所で飢え、歩いた場所で捕食される。
「死ぬ場所」は独立な地点ではなく、通行の多い場所の部分集合に近い。
死の場と踏み荒らし場は対の機構（草が茂る／草が消える）だが、
**空間的には同じ場所に重なる**。同じセルで増える力と減る力が
同時に働いていることになる。

## 第2段 M2（死の場の養分効果）への影響 — 交絡が増えた

第3段の実装で `Demo8Stage2Tests.M2_NutrientBoostRaisesPlantDensityInGraveyardsVersusControl`
が落ちた。48シードで原因を切り分けた（3,000ティック）。

| シード数 | 踏み荒らし | k | 墓場密度 | 他密度 | 比 |
|---|---|---|---|---|---|
| 48 | 無効 | 20 | 0.0476 | 0.0909 | **0.523** |
| 48 | 無効 | 0（対照） | 0.0312 | 0.0895 | **0.348** |
| 48 | 有効 | 20 | 0.0457 | 0.0889 | **0.514** |
| 48 | 有効 | 0（対照） | 0.0377 | 0.0858 | **0.439** |

**養分効果そのものは消えていない**（k=20 の比は 0.523 → 0.514 でほぼ不変）。
変わったのは**対照**で、0.348 → 0.439 に押し上げられた。
結果、養分効果の差は **+0.175 → +0.075 と半分以下に縮んだ**。

原因は M3 で判明した重なりである。通行が多い → 草が減る → 餌が乏しくなる →
そこで餓死する。**墓場は踏み荒らされた場所にできる**ため、
墓場の植物密度は「養分で増える力」と「踏まれて減る力」の合成になり、
死の場単独の効果を測る指標ではなくなった。

3シードでの値は完全に信用できない:

| シード数 | 踏み荒らし | k=20 | k=0 |
|---|---|---|---|
| 3 | 無効 | 1.166 | 0.309 |
| 3 | 有効 | **0.479** | **1.089**（対照が1を超える） |
| 48 | 有効 | 0.514 | 0.439 |

3シードでは対照が 1.089 と有効条件 0.479 を上回り、符号が逆転している。

### 対処: 第2段の M2 テストは踏み荒らしの**効果だけ**を切って測る

検討した3案:

- **案A（テストを48シードに変更）**: 却下。48シード×2条件で70秒かかり、
  pre-push ゲート（現在 EditMode 全体で101秒）に対して重すぎる。
  さらに効果は 1.17倍まで縮んでおり、48シードでも境界的で
  閾値に余裕が無い
- **案B（墓場では踏み荒らしを弱める）**: 却下。機構としては
  「動物は死骸を避ける」で説明できなくはないが、
  **場が場に直接作用する特殊ルール**の追加であり、
  「場は独立に積もり、個体の行動を通じてのみ相互作用する」という
  既存の設計を破る。加えて、テストを通すために世界のルールを足すのは
  SBCE（事前登録して測る）の考え方に反する
- **案C（テストから外して記録のみにする）**: 方向は正しいが、
  そのままだと養分効果の退行を検出できなくなる

採用は**案Cの変形**。テストが確かめたいのは「死の場の養分効果が
生きているか」であって「踏み荒らし込みの合成結果」ではないので、
交絡要因である踏み荒らしの**効果だけ**を無効化して測る
（`trampleSuppression = 0`, `trampleCrushChance = 0`）。

場への書き込みは残すため RNG の消費列は変わらず、
**世界の進行は第2段と完全に同一**になる。実際、この条件での3シード実測は
1.166 / 0.309 で、第2段の記録と一致する。テスト時間も変わらない。

合成結果（踏み荒らし込みの 0.514 / 0.439）は上表として本ファイルに記録する。
