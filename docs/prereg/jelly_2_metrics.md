# jelly_2 事前登録メトリクス

起草: 2026-08-16（実装前）

jelly_1（タグ `jelly-1.1`）が**機構の検証**で止まっているのに対し、
jelly_2 は **環境との結合**を扱う。jelly_1 の prereg §2 で
「J4（水槽統合）は jelly_2 に分離する」と宣言した当のものである。

---

## 1. なぜ jelly_1 に追記しないのか

Phase C の実機で「クラゲが壁に張り付いて動かない」が確認され、
その解として「壁を刺激としてクラゲの神経に入れれば、既存の機構だけで
壁を避けるはず」という筋が出た。機構はたしかに jelly_1 にある
（M-J3b: 側方刺激で進路が偏向し、刺激が消えると復帰。実測 360.0° → 315.1° → 復帰）。

しかし**環境がモデルの中で神経に結合する**ことは、jelly_1 が明示的に
切り出した範囲である:

- §2「J4（水槽統合）は jelly_2 に分離する」
- §5.2「環境・餌・繁殖は jelly_2」
- §6.1「機構の検証であって適応の測定ではない。後者は jelly_2 の領分」

追記で済ませると、**分離を宣言した当のものを戻す**ことになり、
prereg の境界が意味を失う。jelly_2 として立てる。

## 3. K3: 境界からの侵害受容（中核）

### 3.1 何を入れるか

壁に最も近いリングセルへ刺激を入れる。逃避の向きは
**既存の機構（M-J2b: 伝播の時間差 + 減衰勾配）から創発させる**。
新しい操舵則は書かない。

| 決めること | 登録値 | 根拠 |
|---|---|---|
| どのセルに | 壁に最も近い1セル | 実物の侵害受容器は体表に固定され、どれが発火するかは接触が決める |
| どの強さで | `ExcitableParams.ExcitedLevel` と同じ（通常の刺激と同格） | 強さを別に持つと自由度が増え、創発の主張が弱まる |
| いつ | 壁面距離が **傘半径 + 1セル** を下回っている間、**拍動周期 T ごとに1回** | 毎ステップ入れると不応期で半分が空振りし、T = R₀ の谷と同じ現象が起きる（§5.2） |

### 3.2 主張

> **環境が刺激の位置を決め、逃避の向きは依然として創発する。**

これは M-J2b（動物が行き先を決めるのに方向を計算していない）から
**自動的には従わない新しい主張**である。「壁に最も近いセル」を求めるのは
方向の計算だからである。

**分界**: その計算は**環境の側**（`JellyBoundary`）に置く。
動物の内部状態からは方向を作らない。

### 3.3 固定の仕方

| 固定 | 方法 |
|---|---|
| 神経側に方向計算が入らない | grep テストの走査対象は `SimCore/Excitable` + `Fluid/Jellyfish.cs` のまま。**`JellyBoundary.cs` は対象外**（環境の情報を扱う層） |
| 刺激の位置が環境由来であること | 壁の配置を変えたら刺激セルが変わることをテストで固定 |
| 逃避の向きが創発であること | 同じ刺激セルに対し、g を変えると向きが反転する（M-J2b の符号反転境界が生きている）ことを再確認 |

### 3.4 判定（**実行前に決める**）

| ID | 判定 | 合格条件 |
|---|---|---|
| **M-K3a** | 壁への接近が減る | 止水・同一シードで、侵害受容ONのほうが**壁面距離の時間平均が大きい**。48シードでの符号一貫 ≥ 40/48 |
| **M-K3b** | 静止しない | 侵害受容ONで、**実移動速度の時間平均が遊泳目標の 50% 以上**を保つ（OFF では 0 に落ちる） |
| **M-K3c** | 部屋を使う | 訪れた格子セルの数（被覆）が OFF より多い。48シードでの符号一貫 ≥ 40/48 |

**M-K3b が要である。** Phase C で「泳げている」と報告する指標
（推力からの積分）が「止まっている」個体に出ていたので、
**実移動で測る**ことを判定に明記する。

### 3.5 予想（先に書く）

**往復に落ち着くと予想する。**

M-J3b は「刺激が消えると**元の進路に復帰する**」である。壁から逃げれば
刺激が消え、ペースメーカーが元の向きへ戻すので、壁へ戻ってまた逃げる。
持続的な進路変更にはならない。

したがって:

- **M-K3a・M-K3b は合格する見込み**（張り付きは解消する）
- **M-K3c は不合格または僅差の見込み**（部屋を泳ぎ回るところまでは行かない）

**この予想が当たった場合、それは失敗ではない。** 持続的な進路変更には
**体の向きが状態として残る**ことが要り、それが K2 の傘の軸である。
K3 を K2 の後に置いているのはこのためで、K3 単独では往復までが上限、
という理解を先に登録しておく。

**予想が外れて M-K3c が合格した場合**は、その機構（なぜ復帰しないのか）を
記録すること。M-J3b の復帰性と矛盾するので、どちらかの理解が誤っている。

## 4. K4: 2×2 要因計画

`flow_colony.py` の測定から置き換えた仮説をそのまま登録する。

> **剛性は群体成立の前提条件であり、流れは剛性がある場合にのみ利益に転じる。**

| 条件 | プロトタイプ実測 |
|---|---|
| flexible + 流れ | 0.183 |
| rigid + 流れ | **0.270** |
| rigid + 静水 | 0.218 |

**2×2 要因計画（flow × rigid）、48シード。**
交互作用の符号が上の並びと一致するかを見る。

**検定台の限界を併記する**（`docs/prototypes/README.md`）:
プロトタイプはビューア版の「link が 0.03 まで刈られる」現象を再現して
おらず、**検定台そのものが未検証**である。M-F2 の逆向きの結果は
「流れ仮説の反証」としては読めない。

### 4.1 遺伝子化

jelly_1 §5.2 の規約を引き継ぐ。

- 受容器から運動への接続は**速度（θ）と旋回率の2経路を独立に持つ**。
  片方だけの実装を禁止する
- **旋回率への結合係数は手で置かず、遺伝子とする**

根拠（M-K1、`homeostat.html`）: 用量反応は単調（係数
0 / .006 / .012 / .024 / .048 / .096 に対し 0.492 / 0.510 / 0.512 /
0.553 / 0.586 / 0.664）だが、**生存には最適値がある**
（0.024 を超えると 42.0 → 39.7 → 38.8 → 31.7）。値を固定すると
「世界定数の設計」ではなく「個体の戦略パラメータの調整」になり、
創発の主張が無効になる。

## 5. 探索空間の境界（jelly_1 からの申し送り）

遺伝子探索を始める前に、**既知の落とし穴を境界として登録しておく**。

### 5.1 限定1: 重ね合わせは密な刺激では線形でない

M-J2d（ベクトル平均）は**2点・90°離れの範囲でのみ**成立する。
0°・90°・180° の3点同時刺激では:

| | 値 |
|---|---|
| ベクトル平均の予測 | 270° |
| 実測 | **90°（正反対）** |
| 移動距離 | 0.775（単一刺激 11.921 の 6.5%） |

各セルは不応期のあいだ1度しか発火できないので、重なった波は
足し算にならない。**侵害受容が複数の壁から同時に入る状況（部屋の隅）は
この領域に入る。** 隅で逃避が破綻することを想定しておくこと。

### 5.2 観察A: T = R₀ の谷

拍動周期 T を遺伝子にするなら、探索空間はこうなっている。

| T | 刺激が入った | **波が出た** | 平均速度 |
|---:|---|---|---:|
| 15 (= R₀+1) | 107/107 | 107/107 | **0.792（最速）** |
| **14 (= R₀)** | **115/115** | **58/115** | **0.428（谷）** |
| 13 | 62/124 | 62/124 | 0.462 |

- 上限側: 制約なし（遅いだけ）
- **最速は T = R₀ + 1**
- **T = R₀ ちょうどは谷**（両隣より遅い）。**勾配法だと嵌まりうる**
- T < R₀ は実効的に 2T に折り返す（探索が無駄になる領域）

**「刺激が入った」と「波が出た」は別物である。** 受理数だけを数えると
この谷は見えない。同じ理由で、侵害受容も**入れた回数ではなく
波が出た回数**で記録すること。

## 6. 水槽側の申し送り（Phase C から）

| 項目 | 値 | 出所 |
|---|---|---|
| 目標流速 | **0.03 m/s**（既定） | 遊泳 0.04 m/s に対し、0.08 では流れが2倍速くほぼ流されるだけになる |
| 遊泳速度 | **0.04 m/s** | 実測で目標比 1.000 |
| 傘径 | 15cm（既定） | 拍動が知覚に届く。変形量の誇張は不要だった |
| 拍動周期 | 1.0 秒（神経 40Hz × 40 ステップ） | 流れ場 20Hz と整数比 2:1 |
| 壁の反発 | **無効（0.00）** | 旋回が無い状態では釣り合うだけ。K2 の後に見直す |

**流速と遊泳速度の比が 1 付近であること**が、「流されている」のか
「泳いでいる」のかを見分けられる条件である。判定には
**止水モード（流速 0.00）**を使う。流れがある状態で目視判別するのは
原理的に難しい（周囲との相対速度が見えないため）。

## 7. 判定の測り方（Phase C の失敗を繰り返さない）

| 規約 | 理由 |
|---|---|
| **実移動で測る** | 推力からの積分は、壁で移動が拒否されても進む。静止した個体に「遊泳 0.0400 m/s（目標どおり）」と出ていた |
| **平均で測る。瞬時値を平均として読まない** | 瞬時の遊泳速度は1拍動で 0.19〜0.0004 m/s まで振れる。1秒間隔の標本化は拍動周期と一致するので位相が固定される |
| **48シード** | 3〜5シードでは指標が数倍単位で振れる（CLAUDE.md） |
| **パネルに出す値はログにも出す** | 装着中は数値を読み上げられない（CLAUDE.md） |
| **比・向きだけでなく大きさの絶対値も判定に置く** | K2 の判定7件はすべて比・向き・恒等性で、大きさを見るものが無かった。全部通ったのに実機では目標の 2.7%（1.07mm/s）で止まって見えた。**変位が出ることと視認できる速度で出ることは別**（追記9） |

## 追記1: K1（抗力係数の逆算）の手順（2026-08-16、計測前に登録）

### A1.1 なぜソース定数を読むだけでは駄目か

`jelly_side.html` の体の力学は毎ティックこの形をしている。

```js
bell.vx += dux*J;                       // 噴流の推力
bell.vx += Fx*0.9*CS/M;                 // 浸漬境界の反作用
bell.vx *= 0.985;  bell.om *= 0.95;     // 抗力（1次減衰）
```

`0.985` をそのまま持ってくることもできるが、**それは有効な抗力ではない**。
浸漬境界の反作用 `Fx` も速度に依存するので、実際の減速は 0.985 だけでは
決まらない。減衰係数だけを読むのは「理論値を使わない」の趣旨を外す。

**走らせて測る。**

### A1.2 計測手順（区間・除外を先に固定する）

| ID | 測るもの | 手順 |
|---|---|---|
| **M-K1a** | 並進の抗力 τ_trans | ペースメーカー停止・流体静定後に `vx = v0` を与えて惰行。**\|v\| が 0.8·v0 → 0.2·v0 の区間**で `ln\|v\|` を直線当てはめ |
| **M-K1b** | 回転の抗力 τ_rot | 同じ手順を `om = ω0` で |
| **M-K1c** | 推力 | ペースメーカーONで定常後、**5拍動（1150ティック）を捨ててから5拍動**の平均速度 |

当てはめ区間を先に決めるのは、**範囲を後から選べないようにするため**である。

### A1.3 不合格条件

**当てはめの R² < 0.98 なら K1 を保留する。**

「1次減衰」というモデル自体が合っていないことになるので、
**単一の係数に押し込めてはいけない**。その場合は抗力の形から見直す。

### A1.4 単位のアンカー

px/ティック → m/s の換算に2つ要る。**どちらもモデルが与えるもので、
選ぶ余地がない。**

- **時間**: `t%230===10` で拍動 → **1拍動 = 230ティック ≡ 1.0 秒**
  （こちらの `PulsePeriodTicks / 40Hz`）。⇒ 1ティック = 1/230 秒
- **長さ**: 傘の直径 `2·Rb` px ≡ `BellDiameter` = 0.15 m

### A1.5 ビューポートを固定する（後から選べる自由度）

```js
const Rb = Math.min(W*0.30, 150);
```

**傘の大きさがビューポート幅で変わる。** スマホ（W≈390）で 117px、
デスクトップ（W≈1200）で 150px（頭打ち）。流体格子は `CS=6` 固定なので、
**傘が格子何個ぶんかが画面によって変わり、流体の効き方も変わる。**

- **登録するビューポート: W=390, H=844**
  （プロトタイプは `maximum-scale=1`・safe-area 対応のスマホ前提）
- **併せて W=1200, H=800 でも測り、無次元比 τ_rot/τ_trans が
  両者で一致するかを見る**

比が一致すれば抽出は頑健。**食い違えばそれ自体が知見**で、
ビューポートを固定した旨を明記して進む。
判定を後から作らないよう、この頑健性チェックも手順に含める。

### A1.6 主たる成果物

C# へ持ち込むのは**無次元比 τ_rot/τ_trans を第一**とする。
px もティックも消えるので、換算アンカーの誤りに影響されない。
τ_trans 自体は時間アンカー経由で秒に直す。

### A1.7 参考値（**合わせにいかないために先に書く**）

ソース定数から素朴に計算すると:

| 量 | 素朴な計算 | 現行の C# |
|---|---|---|
| τ_trans | -(1/230)/ln(0.985) ≈ **0.29 秒** | `Drag=0.1 @40Hz` → 0.24 秒 |
| τ_rot | -(1/230)/ln(0.95) ≈ **0.085 秒** | 未実装 |
| τ_rot / τ_trans | **≈ 0.30**（回転の抗力が並進の約 3.4 倍） | — |

**これは実測ではない。** 反作用を含んだ実効値は A1.2 の手順で測る。
この数字を知ったうえで測ると無意識にそこへ寄せる力が働くので、
**自覚して先に明記しておく**。実測がこの値から離れても、
手順どおりなら実測を採る。

### A1.8 ハーネスの検証（本計測の前）

物理は 240 行中の 50〜186 行に閉じており、DOM に触れているのは
canvas 設定・入力・描画だけなので、node へ切り出して無描画で回せる。

**本計測に入る前に、ハーネスがプロトタイプと同じ振る舞いを出すことを
確認する**:

- 拍動周期が 230 ティックであること
- ペースメーカーONでの定常速度が得られること（発散も停止もしない）

## 追記2: K1 の計測結果 — **M-K1a / M-K1b 不合格。K1 を保留する**（2026-08-16）

### A2.1 ハーネスの確認（A1.8）は通った

| 確認 | 結果 |
|---|---|
| 拍動周期 | **ちょうど 230 ティック**（5周期とも） |
| 定常遊泳 | 得られる。発散も停止もしない |

確認スクリプト自体のバグを2件直してから通した。
1件目は**空振りの合格**（拍動を0件しか検出できていないのに
`[].every()` が true を返して「OK」と表示していた）。
2件目は `reset()` が `world.pace` を戻しておらず、前の計測で切った
ペースメーカーが次へ漏れていた。

### A2.2 M-K1a / M-K1b: **登録した当てはめ区間で標本が取れない**

惰行させると、速度は減衰しない。**振動する。**

登録ビューポート（W=390）で `v0` を与えた直後の `v/v0`:

```
並進  0:1.558  1:0.375  2:0.952  3:0.025
回転  0:2.453  1:1.892  2:2.144  3:1.732  4:1.764  5:1.492 …
```

頑健性チェック（W=1200）はさらに極端で、**注入値の 42 倍へ跳ね上がり、
以後 12〜57 のあいだをティックごとに往復し続ける**:

```
並進  0:42.345  1:22.359  2:41.088  3:11.755  4:48.983  5:11.621  6:56.833 …
```

`|v|` が 0.8·v0 → 0.2·v0 を単調に通過しないので、**A1.2 で登録した
当てはめ区間そのものが取れない**。R² を計算する手前で止まっている。

### A2.3 判定: 保留（A1.3 のとおり）

プロトタイプの操作系は「左/右タップ = その側だけ収縮（旋回）」で、

| **片側**（旋回） | ペースメーカーを止め、`t%230===10` で `fireNerve(0,t)` **のみ** |
| **両側**（対照・直進） | プロトタイプ既定のペースメーカーそのまま |

| 量 | 定義 |

| 比 | 回頭角 ÷ (経路長 / 傘の直径) = **[度 / 体長]** |

## 追記7: K2 の設計と判定（2026-08-16、**実装前に登録**）

### A7.1 傘の軸を状態として持つことと M-J2b

M-J2b が禁じているのは「**動物が行き先を決めるのに方向を計算すること**」で、
禁止されている形は「刺激を感じる → 目標方向を計算 → そこへ操舵する」、
つまり**設定値を持つ制御器**である。

傘の軸はそれに当たらない。線引きは1点:

> **軸は積分されるだけで、代入されない。**

位置 `X, Y, Z` はすでに状態だが、これが M-J2b を破っているとは言わない。
速度は各セルの局所的な寄与の総和として出てきたもので、方向を計算した
結果ではない。**姿勢は位置の1階微分上の同じ構成**である。

```
既存（並進）: m_ModelVx -= amp * m_Cos[i];        // 局所的な寄与の総和
K2（回転）  : m_ModelOm += amp * LeverArm(i);     // まったく同じ形
```

**留保（自己申告）**: 軸が存在すると推力は `J × 軸` になり、
方向がベクトルとして力に入る。ただしこれは「どこへ行くかの計算」ではなく
「体が現にどう向いているか」を読んでいるだけである
（魚の尾の推力が体軸に沿うのと同じで、魚は進路を計算していない）。

**grep だけでは守れない。** 主張を不変量として固定する（A7.3 の M-K2a/c/e）。
変数名は物理量で付ける（`axis`, `tilt`, `om`）。意図を表す名前
（`targetDir`, `heading`）にしない。

### A7.2 復元トルク

**入れる。既定 ON、アブレーション可能。**

理由:
- 逆さまのまま泳ぐクラゲは「生きて見えない」の最大要因になりうる。
  これまでの「環境に反応しない」「水平にしか泳げない」より強く違和感を生む
- **復元は「往復問題」を消さない。** 時定数で立ち直るので、壁から離れる
  時間は稼げる。§3.5 の予想（往復に落ち着く）は生きたまま
- 復元の強さは実測から取れない（追記6 の打ち切り）。したがって §4.1 の
  既定に従い**遺伝子とする**。K2 では「経路が存在し、係数が外部から
  与えられる形になっている」ことのみを実装要件とし、値の探索は K4 に送る
  （jelly_1 §5.2 とまったく同じ形）

**実機で切れるようにする**（右手トリガー）。「逆さまが直らない」と
「逃避が永続する」のどちらが体験として重いかは実機で見るまで分からない。

### A7.3 判定（**絶対閾値ではなく対照との比**で置く）

K1 で対照が決め手になった。両側発火が片側の 63% 回っていたのを、
絶対閾値だけなら「0.963 は惜しい」と読んでしまった。

| ID | 判定 | 合格条件 |
|---|---|---|
| **M-K2a** | **対照: 対称なら回頭しない** | 対称発火 800 ステップで \|Δ軸\| < 0.5 度 |
| **M-K2b** | 非対称で回頭する | \|Δ軸\| が **対照（M-K2a）の 10 倍以上** |
| **M-K2c** | 鏡像対称 | 左のみ／右のみで符号が反転し、大きさが 10% 以内で一致 |
| **M-K2d** | 推力が軸に沿う | 止水での**変位の向きが軸の向きと 20° 以内**で一致 |
| **M-K2e** | **神経は軸を見ない** | 初期軸を変えてもリングの ContentHash が一致 |
| **M-K2f** | 決定論 | 同一入力から同一ハッシュ |
| **M-K2g** | **復元の有無で M-K2b が変わらない** | 復元 ON / OFF の両方で M-K2b が合格 |

**M-K2e が線引きの核である。** 神経が軸を見られないなら、
何かへ向けて操舵することは原理的に不可能。grep より強い。

**M-K2d を「鉛直に何 m 進むか」にしない。** 変位と軸の一致にすれば
magic number を置かずに「推力の向きは傘の軸」をそのまま検証できる。

**M-K2g は K1 の罠の再発防止である。** 復元が強すぎると回頭を打ち消し、
判定が復元係数依存になる。K1 で既定 0.06 が「反発ありと無しで差が出ない」
となったのと同じ形。**復元係数を上げて M-K2b が落ちる場合、
その係数は探索範囲の上限として記録する。**

### A7.4 上下方向の判定

ヘッドレスでは止水が厳密に作れる（`Step(dt, 0, 0, 0)`）ので、
流れに運ばれる分と切り分ける必要がない。M-K2d はここで測る。

実機では**右手A の 0.00（止水）**を使う。既に入っている。

## 追記9: 実機で K2 が止まった — 正規化の欠落（2026-08-16）

### A9.1 現象

止水でクラゲが**その場で傾くだけで移動しない**。Phase C（2D リム収縮）では
同じ条件で 0.04 m/s で直進し、壁に到達していた。

### A9.2 原因: 換算係数が 2D モデルのまま

`SpeedScale` は `CalibrateSpeedScale`（**2D リム収縮**のモデルを走らせる）で
出していたのに、噴流モデルの速度へそのまま掛けていた。推力の形が違うので
**桁が違う**。

| モデル | 止水での実移動 | 目標比 |
|---|---|---|
| Phase C（2Dリム） | 0.040000 m/s | 1.0000 |
| **K2（噴流）修正前** | **0.001067 m/s** | **0.0267** |
| K2（噴流）修正後 | 0.039980 m/s | 0.9995 |

**1.07 mm/s** は目には静止と区別がつかない。

### A9.3 なぜ判定7件を全部通ったのか

**M-K2d は変位の「向き」しか見ていなかった。** 大きさの下限は
「0 でないこと」を保証する `1e-4` m（800ステップで 0.1mm）だけで、
これは空の検証を防ぐためのガードであって速度の判定ではない。

> **変位が出ることと、視認できる速度で出ることは別である。**

M-K2a〜h はすべて**比・向き・恒等性**を見る判定で、**大きさの絶対値を見る
判定が1つも無かった**。K1 では「対照との比」が要ると学んだが、
今回は逆に「絶対値も要る」場面だった。§7 の測り方の規約に追加する。

### A9.4 追加した判定

| ID | 判定 | 合格条件 |
|---|---|---|
| **M-K2i** | 噴流モデルが目標速度で泳ぐ | 経路長ベースの平均速度が目標の ±5%（0.02 / 0.04 / 0.10 で確認） |
| **M-K2i'** | 2つのモデルの速度が一致 | 2Dリムと噴流の差が 5% 以内（実機で切り替えて速さが変わって見えない） |

経路長で測るのは、噴流モデルが旋回するので正味変位が曲がったぶん短くなるため。

### A9.5 較正の落とし穴（実装メモ）

較正は本体を走らせて測るので、**`Pacemaker = false`（判定側が発火を制御する
ためのフラグ）を継承すると刺激ゼロ → 速度ゼロ → 係数 0 になり、全部止まる**。
較正は必ずペースメーカーを働かせる。測るのは「この個体が自分のペースメーカーで
どれだけ速く泳ぐか」であって、判定側の都合とは無関係である。

### A9.6 未確認: 刺激注入で傾きがリセットされて見えた件

**このセッションのログが無い**（キャプチャをアームする前に起動された）ため、
確認できていない。`InjectStimulus` は湧かせ直しをしないので、
**復元トルク（既定 0.5）が傾きを平衡値へ引き戻したもの**＝ M-J3b の
「刺激が消えると元の進路に復帰する」の現れ、という可能性が高い。
次のセッションでログを取って確かめる（傾きは毎秒ログに出している）。

## 追記10: 沈降を世界法則として入れる（2026-08-16、**実装前に登録**）

### A10.1 なぜ入れるか

実機で「重力がないため自然に見えない」と観察された。これは不具合ではなく
**設計の欠落**である。

- **姿勢に意味が生まれる。** 沈降が無いと、傾いても旋回しても「何のために」が無い。
  拍動を止めれば沈むなら、**拍動は沈まないための努力**になり、傾きは
  「どちらへ逃げるか」の意味を持つ。K3 の侵害受容も、沈降がある世界でこそ
  「逃げる」が成立する
- **世界法則であって戦略パラメータではない。** 体の密度と水の密度の差は
  種の性質で、個体が調整するものではない。roadmap「世界定数は設計してよいが、
  個体の戦略パラメータを手で調整したら創発の主張が無効になる」に照らして
  **設計してよい側**
- **プロトタイプにも先例がある。** `jelly_side.html` は
  `bell.vy += 0.0025`（"slight negative buoyancy"）を持つ

**Phase D の浮力項とは別物。** あちらは**水**が動く話（温度差 → 流れ場）、
こちらは**体**が沈む話である。

### A10.2 定義と値

> **沈降速度 = 遊泳速度に対する比**（既定 **25%** = 0.01 m/s）

絶対値を直接置かず比で置くのは、**「拍動と沈降のどちらが勝つか」という関係を
設計している**ことを明示するため。大きさは K1 の打ち切りにより実測から
取れないので設計値だが、世界定数なので遺伝子にはできない。

**下向き（部屋座標の −Y）の定数速度**として位置に足す。自力遊泳ではないので
`SwimPath` には積まない。**較正では無効にする**（沈降ぶんまで正規化すると
遊泳速度が目標からずれる）。

### A10.3 実機で振る

| 操作 | 内容 |
|---|---|
| **右手トリガー（長押し）** | 沈降 0% → 25% → 50% |
| **左手トリガー（長押し）** | **拍動の停止／再開**（トグル） |

短押しは既存のまま（右 = 復元トルク、左 = 刺激注入）。
**左が神経、右が体の物理**という対応で覚えられる形にする。

「拍動と沈降の釣り合い」がどこで体験として成立するかは見てしか判断できない。
拍動を止めて沈むところを見せるのが、「拍動＝沈まないための努力」の
最も直接的な提示になる。

**拍動の停止は湧かせ直さない**（位置を保ったまま沈むところを見る）。
実行時の入力として扱い、パラメータは変えない。

### A10.4 判定（**実装前に決める**）

| ID | 判定 | 合格条件 |
|---|---|---|
| **M-K2j** | 拍動を止めると沈む | 止水・拍動停止で、鉛直の平均速度が沈降速度と ±10% で一致 |
| **M-K2k** | 拍動していれば沈まない | 拍動中の**正味の高さ変化**が、同じ時間の沈降だけの場合の **20% 未満** |
| **M-K2l** | 沈降が K2 の判定を壊さない | 沈降 0 / 25 / 50% のすべてで **M-K2i（目標速度）と M-K2d（軸一致）が合格** |

**M-K2k が「拍動＝努力」の内容である。** 沈むはずのものが沈まないでいる、
という関係を数値で固定する。

**M-K2l は K1 の教訓の適用。** 新しい世界法則を足したときに既存の判定が
静かに壊れていないかを、**同じ掃引の形**で確かめる（追記7 の M-K2g と同型）。

### A10.5 不合格条件

- **M-K2k が落ちる（拍動しても沈む）**場合、沈降が強すぎるか推力が弱すぎる。
  比 25% を設計値として見直す。**そのとき比を動かした事実を記録する**
- **M-K2l が落ちる**場合、沈降の入れ方（位置に足す形）が間違っている。
  較正や軸との関係を見直す

### A10.6 予想

**M-K2j・M-K2l は合格、M-K2k も合格する見込み。** 遊泳 0.04 m/s に対し
沈降 0.01 m/s なので、拍動していれば十分に打ち勝つ。

ただし**軸が下を向いているときは沈降と推力が同じ向きになり、速く沈む**。
これは不具合ではなく、復元トルクが姿勢を立て直すまでの過渡である。
M-K2k は軸が上向きの定常状態で測る。

## 追記11: 沈降比を 0.25 → 0.90 に変更（2026-08-16、A10.5 の手続きに沿う）

### A11.1 M-K2k が落ちた。ただし**予想と逆向き**に

A10.6 は「M-K2k も合格する見込み。遊泳 0.04 に対し沈降 0.01 なので拍動が
十分に打ち勝つ」と書いた。打ち勝ちすぎた。

**拍動中に 0.0299 m/s で上昇し続ける。** 20秒で 0.6m 上がり、
2m の部屋なら1分で天井に着く（傾き 2.3°、軸はほぼ真上）。

### A11.2 掃引: 釣り合いは比 ≈ 1.0

| 比 | 沈降 m/s | 正味 m/s | 20拍動での高さ変化 |
|---:|---:|---:|---|
| 0.00 | 0.0000 | +0.0399 | +0.799m 上昇 |
| **0.25（登録値）** | 0.0100 | **+0.0299** | **+0.599m 上昇** |
| 0.50 | 0.0200 | +0.0199 | +0.399m 上昇 |
| 0.75 | 0.0300 | +0.0099 | +0.199m 上昇 |
| **0.90（新既定）** | 0.0360 | **+0.0039** | +0.079m（ほぼ漂う） |
| 1.00 | 0.0400 | −0.0001 | −0.001m（釣り合い） |
| 1.10 | 0.0440 | −0.0041 | −0.081m（拍動しても沈む） |

**「拍動＝沈まないための努力」は比が 1 の近くでしか成立しない。**
それ以下では単なる上向き推進であって、努力ではない。

### A11.3 変更した値と理由

> **沈降比 0.25 → 0.90。**

- 1.0 ちょうどにしないのは、正味 0 だと**鉛直に一切動かなくなる**ため
- 1.0 を超えると拍動しても沈む＝ M-K2k（拍動していれば沈まない）が落ちる
- 0.90 は「わずかに拍動が勝つ」点

**A10.5 の手続きどおり、比を動かした事実をここに記録する。**
不合格の向き（沈みすぎ）だけを想定していて、逆向き（上がりすぎ）を
想定していなかったことも記録する。

### A11.4 テスト自身の誤り（3例目の系統）

M-K2k は最初 `Math.Abs(Δ高さ)` で測っており、**上昇 0.599m を「沈んだ」と
報告して落ちた**。主張は「沈まない」であって「動かない」ではない。
上昇と沈降を区別する形に直した。

**判定の向きを取り違える**のは、「空の検証」「位相で標本化」に続く
同じ族の誤りである。

### A11.5 実機で振る（A10.3 の更新）

| 操作 | 内容 |
|---|---|
| 右手トリガー**長押し** | 沈降 0.90 → 0.00 → 0.50 → **1.10** |
| 左手トリガー**長押し** | 拍動の停止／再開 |

**1.10 を選択肢に入れた**（拍動しても沈む領域）。判定としては不合格側だが、
**体験としてどちらが「生きて見える」かは別**なので実機で比べられるようにする。

### A11.6 既存判定への影響

沈降は自力遊泳ではないので、**速度を測る判定はすべて沈降を除いて測る**。
`SwimDistanceInStillWater` と M-K2i 群を、位置から `SinkPathY` を引いた
高さで測る形に直した（Phase C の 2D モデルの判定も同じ扱い）。

M-K2l（沈降 0 / 0.5 / 0.9 / 1.1 で M-K2i と M-K2d が合格）は**全条件で合格**。
294件パス。

1. **変更前の判定文と実測を消さない。** 追記10 A10.4 の M-K2k

### A12.2 設計値 1.10 は**実測ではなく実機の印象から選んだ**

### A12.3 主張の弱め方

> **旧: 拍動していれば沈まない**（M-K2k）
> **新: 拍動は沈降を遅くする**（M-K2k′）

正味 −0.0041（9.3%）。**比 1.5 でも 0.0600 に対し −0.0201（33.5%）で

## 追記13: K3 の受容器規則・判定の分割・測ってから書く予想（2026-08-18、**実装前に登録**）

### A13.1 受容器規則を「最も近い1セル」から「体表の位置」へ変える

§3.1 の登録値「どのセルに = **壁に最も近い1セル**」は、**床に対して破綻する**。

傘の縁の各セルについて「床までの距離の差」（傘径 0.15 m、セル 0.08 m）:

| 状況 | 縁の最近点と最遠点の距離差 | セル数 |
|---|---:|---:|
| 床の真上・傾き 0° | 0.000 m | **0.00** |
| 床の真上・傾き 5.05°（実測平均） | 0.0132 m | **0.17** |
| 床の真上・傾き 13.0°（実測最大） | 0.0337 m | **0.42** |
| 垂直な壁 | 0.150 m | 1.88 |

距離場は**整数チャンファ**なので 0.42 セルの差は読めない。床に対しては
16セル全部が同値を返し、**「最も近いセル」はタイブレークの実装が決める**。
それは環境が決めた向きではなく**こちらが書いた向き**であり、
§3.2「環境が刺激の位置を決める」が成立しない。

**沈降 1.10 ではこれが定常状態である**（例外ケースではない）。

> **新しい規則: 各リングセルの実位置（中心 + R·r̂ᵢ）を求め、
> そのセルが壁の帯に入っていれば発火させる。argmax もタイブレークも使わない。**

| 状況 | 発火するセル | 帰結 |
|---|---|---|
| 垂直な壁 | 壁側のみ | 非対称 → 旋回（§3.1 の意図どおり） |
| 床の真上・上向き | **16セル同時** | 対称 → M-K2a より旋回せず、推力のみ変化 |
| 傾いて床へ | 下がった側が先 | 非対称 → 立て直す向き |
| 隅 | 2方向のセル群 | **限定1（§5.1）の領域** |

- 実物の侵害受容器は体表に分布しており、**「最も近い1点を計算する」器官は無い**。
  argmax のほうが不自然な実装だった
- 主張が強くなる。方向の計算がどこにも無い
- **帯幅は「傘半径 + 1セル」→「1セル」**。傘半径ぶんは受容器を縁に置いたことで
  自動的に入る

**grep の分界は変えない。** この計算は `JellyBoundary`（環境の層）に置き、
走査対象は `SimCore/Excitable` + `Fluid/Jellyfish.cs` のまま。

### A13.3 予想の前に測る量（**対照つき・位相掃引つき**）

## 追記14: K3 の結論・沈降OFF判定の取り下げ・発火規則の変更（2026-08-19）

### A14.1 K3 の機構的な結論

> **対称発火は「逃避」ではなく軸方向のパワーストロークである。
> 逃避が成立するのは復元トルクとの合作としてであって、侵害受容だけでは成立しない。**

体表規則（追記13 A13.1）で床の真上に来ると縁が全周同じ高さに入り、**16セルが
同時発火する**。対称発火は M-K2a より**構造的にトルク 0** なので、推力は軸方向にしか
出ない。したがって:

| 面の位置 | 結果 |
|---|---|
| **軸の反対側**（上向きの個体にとっての床） | 推力が面から離れる向き → **逃げられる** |
| **軸の側**（上向きの個体にとっての天井） | 推力が面へ押し込む向き → **貼り付く** |

**床から逃げられるのは復元トルクが軸を上へ保っているからである。**
侵害受容そのものが方向を持っているわけではない。これが K3 の答えである。

**天井の貼り付きは塞がない**（方針B）。軸側刺激で拍動を抑制するような新しい結合は
K3 の射程を超えるうえ、塞ぐとこの発見が「対処済みの不具合」に見えてしまう。
実世界（沈降 1.10）では天井到達自体が稀で、「上に行きすぎると天井で止まり、
沈降で戻る」は水槽の生き物として許容範囲とする。**実機の確認項目に入れる。**

実測（沈降 OFF、噴流モデル、シード40）:

| | 侵害受容 ON | OFF |
|---|---|---|
| 4000ティック後の位置 | 天井 Y=2.00 で固定 | 天井 Y=2.00、X はわずかに漂う |
| 接触セル | **16/16** | — |
| 傾き | **0.0°（完全に固定）** | 2.3〜4.0° で振動 |
| 実移動（後半平均） | **0.00000 m/s** | — |

**傾きが 0.0° に固定される**のが要点である。対称発火にトルクが無いので、
逃げるための非対称を**永久に作れない**。

### A14.2 沈降 OFF の判定（M-K3a・M-K3c）を取り下げる

§3.4 の M-K3a/M-K3c は**噴流モデルと沈降が入る前**の登録である。
噴流モデルでは沈降を切ると全個体が上昇し続けて天井に達するので、
M-K3a は「**天井に貼り付いた個体同士**」を比べていた。

> **取り下げの理由: 前提の変化。** 沈降 OFF の世界は噴流モデルの導入によって
> 検定台として成立しなくなった。「天井に貼り付いた個体同士の比較」を
> 判定と呼び続けることはできない。

**M-K2k と同じ扱いとし、判定文と不合格の実測を残す**（消さない）:

| ID | 登録された判定 | 実測 | 扱い |
|---|---|---|---|
| **M-K3a** | 壁面距離の時間平均が ON > OFF、48シードで ≥40/48 | **0/48**。ON 0.0400 m = OFF 0.0400 m（ともに天井で半セル） | **取り下げ** |
| **M-K3c** | 被覆が ON > OFF、48シードで ≥40/48 | **29/48**。被覆は ON 18.4 対 OFF 14.8 と増えてはいる | **取り下げ** |

M-K3c は符号としては増加側だが、これも天井に達したあとの水平方向の漂いを
数えており、意味のある被覆ではない。

**§3.5 の原予想「往復に落ち着く」も、沈降 OFF の世界に対する予想だったので
同時に効力を失う。** 削除はしない。

判定は **M-K3b（沈降 ON のみ）と M-K3d** に一本化する。

### A14.3 発火規則を「侵入時に1回」へ変更（§3.1 の登録値の変更）

§3.1 の登録値は「帯を下回っている間、**拍動周期 T ごとに1回**」だった。
実装では帯を出入りするたびに数え直していたため、壁と床に同時に接する状況で
**撃ちすぎ**が起きた。

**変更前の実測**（沈降 1.10、床から 0.30 m、8000ティック、48シード）:

| | 値 |
|---|---|
| 着底したシード | **6/48** |
| 着底した個体の侵害受容の発火回数 | **67〜162回** |
| 漂えた個体の発火回数 | **16回** |
| 着底した個体の侵入位相 | 3, 4, 3, 5, 20, 5 |

**位相の死角（7〜14）とは無関係だった。** 撃ちすぎた個体が沈んでいる。
不応期が飽和してペースメーカーの進行波を潰しており、§3.1 が警告した
「毎ステップ入れると不応期で空振り」が、出入りのたびの数え直しで再現している。

> **新しい規則: 帯に**侵入した時**に1回だけ発火する。帯を出るまで再発火しない。**

周期 T の管理そのものが不要になる。漂う個体は「入る → 撃つ → 出る → 沈む →
入る」の周期を**環境が決める**形になり、こちらでは選べない。

### A14.4 K4 への申し送り: 飽和は限定1 の現れである

撃ちすぎによる飽和は §5.1 の限定1（密な刺激では重ね合わせが線形でない）が
**生存に直結する形**で現れたものである。K4 で拍動周期を遺伝子にするとき、
**拍動周期と刺激頻度の干渉**という形で選択圧になる。§5.2 の T = R₀ の谷と
同じ族の現象なので、探索空間の理解に加える。

### A14.5 M-K3e の実測（追記13 A13.3 の分岐は「増える」側）

対照 = ペースメーカーのみ 0.04000 m/s。T = 40 の全オフセットを掃引:

| | 値 |
|---|---|
| 効果なし（±10%以内） | **8/40 位相**（オフセット 7〜14 = 不応期の影） |

「入る → 撃つ → 出る → 沈む → 入る」の周期を環境が決める形になるのは

**新規則では天井で侵害受容は不活性である**（ON と OFF が完全に同一）。

### A16.4 天井で ON/OFF が一致する理由

シード40 の天井で、侵害受容が発火しているのに傾き（2.28°）と実移動
（0.00195 m/s）が表示桁まで一致する件。

**「発火が動力学に届いていない」ではない。** 根拠:

| 量 | ON | OFF | 読み |
|---|---|---|---|
| **拍動回数** | **99** | **100** | 侵害受容の刺激がペースメーカーセルを不応期にし、**1拍動を抑制している**。神経に届いている |
| リングの状態ハッシュ（t=4000） | 同一 | 同一 | 摂動は減衰し、同じ極限周期の同じ位相に戻る |
| Y | 1.999997 | 1.999984 | ともに天井 2.000000 に貼り付いている |

したがって一致の理由は2つに分解できる。

- **位置が同じなのは天井のクランプが軸方向の変位を捨てているから。**
  発火が推力を生むことは **M-K3e で測定済み**（32/40 位相で増加、最大 +1466%）。
  推力は出ているが `JellyBoundary.ClampMove` が固体セルへの移動を拒否する
- **傾きが同じなのは対称発火のトルクが構造的に 0 だから**（M-K2a）。
  16セル同時発火では Σ(amp_i · r̂_i) = 0 になる。姿勢に影響しないのは
  当然であって、発火が届いていないことの証拠ではない

**計測の訂正。** `NociceptionCount` は**発火の試行回数**を数えており、
実際にセルが興奮したかは見ていない（全セルが不応期なら空振りでも 1 増える）。
追記15 A15.1 の「2〜11回」は試行回数である。

### A16.5 A14.3 の副作用の記述に追加

「侵入時に1回」の恒久ロックアウトについて:

### A16.6 §5.1 限定1 への追記: 隅の破綻は構造的である

隅での破綻は**2つの異なる発火規則で、異なる機構を通じて、同じ限界に落ちた**。

### A17.4 ログの改修（再セッションの前提）

- **接触セルの分布**を16bitのマスクとして16進四桁で出す（`mask=XXXX`）

| bit | 解剖学的な角度 | 傘上の位置 |
|---:|---:|---|

### A17.5 マスクだけでは面を分離できない（**実測**）

「全16bit = 面、1弧 = 単一の壁、2弧 = 隅」という読み方を最初に書いたが、
**これは誤りである。** 実測:

| 配置 | 接触 | マスク | 弧の数 | 床上 |
|---|---:|---|---:|---:|
| 床 | 16/16 | `FFFF` | 1 | 0.032 m |
| 天井 | 16/16 | `FFFF` | 1 | 1.888 m |
| 単一の壁 | 11/16 | `3FF8` | **1** | 0.960 m |
| **隅（2面）** | 15/16 | `BFFF` | **1** | 0.960 m |
| 隅 + 床 | 16/16 | `FFFF` | 1 | 0.032 m |
| 部屋の中心 | 0/16 | `0000` | 0 | 0.960 m |

**隅は「2弧」にならず、幅の広い1弧になる**（11bit 対 15bit）。
床・天井・隅+床はいずれも `FFFF` で同じである。

> **分類には マスク + 床上の高さ + 壁までの距離 の3つが要る。**
> ログはこの3つを同じ行に出す。M-K3g がこの表を固定している。
