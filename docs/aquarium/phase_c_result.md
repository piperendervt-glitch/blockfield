## この段の射程（**不具合ではない**）

実機で「生きては見えない」と判定された2点は、**jelly_1 の射程そのもの**である。
後から読んだ人が不具合と誤読しないよう明記しておく。

### 1. クラゲは水平方向にしか自力で泳げない

リング神経の収縮が生む推力は**リング平面内にしか出ない**。そのリング平面を
水平に固定しているので、自力遊泳は水平のみで、鉛直は流れに運ばれる分しかない。

テスト `Limitation_SelfPropulsionIsHorizontalOnly` で固定してある。

**外れるのは jelly_2 の段2（噴流モデル）。** 推力の**大きさ**は傘の囲む体積の
dV/dt から、**向き**は傘の軸、**旋回**は収縮の非対称から傘の軸を傾ける
（roadmap 系列2 Phase C-8）。軸が3Dの姿勢を持つので、傾けば上下にも推進できる。

順序は prereg jelly_1 §9 のとおり、**抗力係数を `jelly_side.html` の内部量から
逆算してから** dV/dt に移る（理論値を使わない。roadmap「順序を逆にしない」）。

### 2. クラゲは環境に反応しない

餌・光・刺激への反応は入っていない。prereg jelly_1 §6.1 の
「**機構の検証であって適応の測定ではない**」のとおりで、
環境への反応は jelly_2 の領分である。

この段で確かめたかったのは「神経の状態が姿になって見えるか」であり、
それは達成されている（拍動が知覚に届き、収縮の進行波が傘の形に出る）。

### 3. 鉛直の循環は流れ場にも無い

流れは ψ の curl から作った等方な渦なので、床から天井への持続した循環は
生じない。`FlowParams.BuoyancyWeight` は 0 のまま置いてある。
温度差による浮力項は Phase D。

## 判定の道具

**流れがある状態では、クラゲが自力で進んでいるのか流されているのかを
目で見分けられない。** 周囲との相対速度が見えないので原理的に難しい。
実機セッションで実際に判定不能になった。

対策を2つ入れた。

- **流速 0.00 モード**（右手A の4段目）— 止水なら動く分はすべて自力なので
  一意に判別できる。**判定用**
- **クラゲ近傍の粒子を強調**（傘径の3倍以内を明るく大きく）— **判定の道具ではない。**
  流れとクラゲの推力は別のベクトルなので、移動先が一致しないのは当然であり、
  「粒子を追い越すか」で自力かどうかは判別できない（2026-08-16 の訂正）。
  止水モードがある以上この用途は不要で、**クラゲの周りの水が見えるという
  体験側の価値**として残す

パネルは止水のとき比を出さず `[止水: 動く分はすべて自力]` と表示する
（`swim/flow=0.00` は「自力で進んでいない」と読めてしまうため）。

---

## 止水で顕在化した「壁への張り付き」

軸ごとの拒否は**壁を貫通しないことしか保証しない**。推力の向きは
ペースメーカーの位置で決まっていて**一定**なので、壁に向かって進んだ個体は
壁際で押し続け、そこに張り付いたままになる。流れがあれば押し戻されて
目立たないが、**止水モードを入れて初めてむき出しになった**。

距離場の反発を追加した（`JellyBoundary.Repulsion`）。壁からの距離で
滑らかに落とす二次カーブで、役割は「弾き返す」ではなく
**「壁に沿って離れていく」**こと。推力は書き換えず速度に足すだけなので、
接線方向の遊泳は残り、結果として壁沿いに滑る。

強さは実機で振れる（右手グリップ、0.10 → 0.20 → 0.00 → 0.05 m/s）。
**0.00 は反発なしで、比較のために置いてある。**

### 実機の結果: **どの強さでも効かなかった（無効化した）**

2026-08-16 の実機で 0.05 / 0.10 / 0.20 を振ったが、**どれでも壁の手前で止まった**。
強くすると釣り合う位置が遠くなるだけである。

```
21:37:20  位置=(0.39, 0.28, 0.23)[壁まで11cm] 反発=0.20m/s
21:37:29  位置=(0.39, 0.28, 0.23)[壁まで11cm] 反発=0.20m/s   ← 10秒間まったく動かない
```

原因は**重心まわりの回転が無いこと**。推力の向きはペースメーカーの位置で
決まっていて一定なので、クラゲは一方向にしか進まず、**どの壁にも真正面から
当たる**。位置を押し戻しても推力が同じ向きに出続けるので釣り合うだけである。

事前に「壁の向きが一様でなければ壁沿いに滑るはず、真正面のケースは残る」と
書いたが、**実際には真正面のケースしか起きなかった**。見立てが外れている。

**既定を 0（無効）にした。** 機構は残してあるが、有効にすると「対処済み」に
見えてしまう。旋回が入ったら見直す
（テスト `Wall_RepulsionIsDisabledByDefaultUntilTurningExists`）。

### 指標の欠陥もここで出た

同じログ行が `遊泳=0.0400m/s`（目標どおり）と報告していた。完全に静止して
いるのにである。`SwimPathX` は推力から積分しているので、移動が拒否されても
積分だけは進む。**「泳げている」と読める指標が「止まっている」個体に出ていた。**
瞬時値を平均として読んでいた件と同じ系統である。

位置の差分から測る `実移動` を追加した。意図と結果の食い違いがログで分かる。
