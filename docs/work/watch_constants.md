# Watch（L0）系の定数の由来 — 一覧のみ（C-017 項目5）

`ScannedBandCells = 6f`（48cm）が**根拠なく置かれていた**件を受けての洗い出し。
**この文書では修正しない。**由来が書けるものと書けないものに分けるだけである。

`ScannedBandCells` 自体は C-016 で削除済み（走査済みは床の境界ポリゴンで決めるようになった）。

## 由来が書けるもの

| 定数 | 値 | 由来 |
|---|---|---|
| `L0Ticker.HzDefault` | 20 | **カードの指定**（「20Hz 固定ティック」）。仕様として与えられた値 |
| `WatchView.InstanceBatch` | 1023 | **Unity の仕様。** `Graphics.DrawMeshInstanced` の1回あたりの上限。任意に選べる値ではない |
| `PresenceField.NeverVerified` | −1 | 番兵。ティック番号は 0 以上なので衝突しない |
| `PresenceField.NoHeight` | NaN | 番兵。**0 を使うと「床にぴったり」と区別できない**ので NaN にしてある |
| `HeadPoseProducer.HeadProducerId` | 1 | 識別子。プロデューサが増えたときに 2, 3 を振る |
| `WatchPanel.k_RefreshInterval` | 0.5 s | 表示の更新間隔。**毎フレーム文字列を組むのを避ける**ため。読み取りに支障のない範囲で最大 |

## 由来が書けないもの（根拠を後から付けた、または任意に選んだ）

| 定数 | 値 | 状態 |
|---|---|---|
| `L0Ticker.MaxStepsPerFrame` | 8 | **任意。** 「長い停止のあとに走り出さない」ための蓋だが、なぜ 8 かの根拠は無い。実測では**未装着で止まった時間**がここに当たり、8 を超えた分が「落し」として計上される。**この数が挙動に効いている**（前回 57%、今回 49.8% の落しは全部これ） |
| `WatchField.FloorLift` | 0.01 m | **任意。** z-fighting を避けるだけの「十分小さい値」。実機で確認していない |
| `WatchView` の板の大きさ | セルの 0.85 / 0.5 / 0.12 | **任意。** 見た目の調整値。0.85=測れている床、0.5=測れていない床（小さくして区別）、0.12=板の厚み |
| `WatchView` の足元印 | セルの 0.8 | **任意。** 見た目の調整値 |
| `WatchInput` のグリップ閾値 | 0.7 | **任意。** 誤反応しない程度の値として置いた。実測していない |

## 所見

**「由来が書けない」もののうち、挙動に効いているのは `MaxStepsPerFrame` だけ**である。
残りは見た目の調整値で、間違っていても「見づらい」で済む。

`MaxStepsPerFrame = 8` は**落しティックの定義そのもの**になっている。
未装着でアプリが止まった時間が全部ここを通って「落し」に計上されるため、
**「20Hz を維持できなかった」と「装着していなかった」が同じ数字に混ざる。**
指標の側の問題であり、定数の値の問題ではない。切り分けるなら
「未装着由来の落し」と「処理落ち由来の落し」を別に数える必要がある。

**修正はしない。** 一覧として提出する。
