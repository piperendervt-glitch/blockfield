### C-017 で追加で見つかった不具合（記録が1件も書けていなかった）

端末の再生元ファイルが**私が push したまま更新されていなかった**ことから発覚。

```
UnauthorizedAccessException: Access to the path
"/storage/emulated/0/Android/data/com.piperender.blockfield/files/l0_session.log" is denied.
```

**原因は2つ重なっている。**

1. **`adb push` で置いたファイルは `shell` 所有の `rw-r--r--`** で、
   アプリ（別 uid）から**書けない**。再生元を用意した私の操作が、記録を壊した
2. **`catch (IOException)` では足りなかった。** 権限で飛ぶのは
   `UnauthorizedAccessException` で `IOException` ではないため素通りし、
   **記録できない事実がどこにも出ていなかった**

2 のほうが本体である。**書けていないことを黙らせない**形に直した:
`catch (Exception)` で受け、`RecordState` をパネルとログに出す。
併せて 1 秒ごとに `Flush` する（アプリは force-stop で落とされるので
`OnDestroy` を当てにするとバッファごと失う）。

**目視5「再生 OK」は読み取りだけが成立していた。** 記録は動いていなかった。

## C-024: 多時定数の場の予約（2026-08-20、記載のみ）

**実装なし。τ の具体値も決めていない**（段1b）。

- **τ は場の意味を決める。** 同じ実装で τ だけ変えると別の場になる。
  「どれが正しい τ か」は立たず、**主張を決めると τ が従属する**
  （カバレッジのときと同じ構造）
- **1本では両立しない。**「さっきそこから来た」と「普段こう通る」は別の τ
- **係数による間引きを予約。** 条件を4つ先に置いた:
  **(a)** 探索の前に τ 非依存へ正規化（`deposit × f × τ` で **4桁違う**。
  そのままだと重みは「値域の桁合わせ」を探索する。`NociceptionCount` が
  試行回数だったのと同型 — **係数が測っている対象を確認する**）／
  **(b)** 通行3本だけでは**探索が起きず環が閉じない**。
  鮮度（未知への誘因）と危険（忌避）を最初から並べる／
  **(c)** 場どうしの相関を先に測る（相関していれば係数は分離できない。
  M-K3e の位相死角と同じ種類の準備）／
  **(d)** 形を先に確定（**間違った形の中の最適解しか出ない**）
- **間引きの判定を予約時点で置いた**:
  「係数の絶対値が閾値以下のシードが **40/48 以上**なら、その場は落とせる」。
  閾値は探索の前に決める。**1本も落ちなければそれも結果**（全部要るという主張）

**9行に対して箱は 620×240 でおよそ 6行ぶん。** 7行目以降が背景の外へはみ出していた。

| `描画 n=` が読めない | 6行目 |
| 格子と確からしさが見つからない | 7行目 |

**項目を足すたびに下が押し出される構造**だったので、一度直しても4件目が起きる。

### 対処

- **パネルを 5行へ**（刻印 / 状態 / 段 / 凡例 / 警告）。
  **数値はログから後で読む。装着中に見るのは「そう見えるか」だけ**
- **警告は1行に集約**。異常なしなら「異常なし」、多ければ件数。

- パネルから消した FPS は**ログへ移した**（**ログ側は減らしていない**）

**落ちたから緩めたのではなく、守る対象が意図して小さくなったため。**

- `EveryPanelFieldAlsoAppearsInTheLog` の空検証ガードを 8 → 4（9行 → 5行に対応）
