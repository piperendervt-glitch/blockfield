## C-012 の状態について

**未着手**である。C-006 の報告時に「roadmap の更新（系列2 を停止と記録、
魚の段が落ちる、Phase D の判別）」の実施状況を問われ、`docs/design/roadmap.md`
を検索して**いずれも記録が無い**ことを確認した。
「単独ではやらず v14 の再構成カードに吸収する」との指示に従い、手を付けていない。

なお C-009 と C-011 で roadmap に追記した箇所があるが、いずれも
**系列2 の停止の記録ではない**（横断原則／系列1 再開手順／L0 の設計と負債）ので、
C-012 の範囲とは重ならないと判断している。重なると判断された場合は指示を待つ。

## 取りこぼした指示の記録

同じ型を繰り返さないために、取りこぼした指示そのものを残す。

| # | 取りこぼし | 対処 |
|---|---|---|
| 1 | **パイプの終了コードで失敗を「完了」と報告した**（タグ push が pre-push に拒否されたのに exit 0 と報告） | CLAUDE.md に規約。成否は終了コードでなく**外の状態**で確認する（`git ls-remote` 等） |
| 2 | **追記20 が作られないまま次工程へ進んだ** | ユーザーから内容を受けて登録。以後、参照先が存在しないときは着手前に報告する |
| 3 | **C-012（roadmap の系列2 停止の記録）が未実施のまま次へ進んだ** | 台帳に未着手として明示。セッション後に回す |
| 4 | **L0 の実装カードが渡らず、訂正カードだけが残った**（X-001） | 統合版を C-011 として受領。台帳の新設そのものが再発防止 |

**この4件はいずれも「大きい指示の中の小さい指示」ではなく、
「前提が欠けたまま次へ進んだ」型である。** 台帳は前提の欠落も1行にする
（C-012 の行、追記20 の欠番の記録）。
